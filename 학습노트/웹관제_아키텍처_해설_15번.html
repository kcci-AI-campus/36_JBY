0. 한눈에 — 이 슬라이드가 말하는 것

이 슬라이드를 한 문장으로 말하면?
보드에 모니터를 꽂지 않아도, PC나 휴대폰 브라우저로 보드의 실시간 영상과 상태를 볼 수 있게 만든 구조다. 영상은 영상대로, 상태(정상·주의·위험, 경보 횟수)는 상태대로 따로 보내고, 밖에서도 보이게 Cloudflare 터널을 쓴다.

1. 바탕 지식 — 웹이 어떻게 돌아가나

서버와 클라이언트는 뭔가?
서버는 "달라고 하면 주는 쪽", 클라이언트는 "달라고 하는 쪽"이다. 우리 구조에서 서버는 보드 안에서 도는 웹 프로그램이고, 클라이언트는 휴대폰·PC의 브라우저(크롬, 사파리 같은 인터넷 보는 프로그램)다.
식당에서 손님(브라우저)이 주문하면 주방(서버)이 음식(화면·데이터)을 내준다.
HTTP 요청·응답은?
브라우저가 주소를 치면 서버에 "이 주소의 것을 주세요"라는 편지(요청)를 보내고, 서버가 내용물(응답)을 돌려준다. 이 편지 형식의 약속이 HTTP다. 뒤에 S가 붙은 HTTPS는 편지를 봉투에 넣어 잠근 것, 즉 중간에서 엿보거나 바꿀 수 없게 암호화한 HTTP다.
주소(URL)는 어떻게 읽나? 포트는 뭔가?
우리 보드 주소 하나를 쪼개 보면 이렇다.
http://10.10.15.61:5000/api/status?k=(접속 암호)
부분이름뜻
http://프로토콜HTTP 약속으로 대화한다 (터널 주소는 https://)
10.10.15.61IP 주소보드의 집 주소. 교육장 네트워크 안에서만 통하는 주소다(사설 IP)
:5000포트 번호그 집의 몇 번 창구인지. 한 컴퓨터에 여러 프로그램이 있으니 번호로 구분한다. 우리 웹 서버는 5000번 창구에 앉아 있다
/api/status경로창구 안에서 무엇을 달라는지 (상태를 달라)
?k=(접속 암호)쿼리(추가 정보)접속 암호. 맞아야 열어 준다 (첫 접속 뒤에는 쿠키로 옮겨 주소창에서 지운다)
아파트(IP) · 동·호수(포트) · "택배 주세요"(경로) · 비밀번호(쿼리).
localhost, Local:5000 은?
localhost는 "나 자신(이 컴퓨터)"을 가리키는 특별한 이름이다. 구조도의 Local:5000은 "보드 자기 자신의 5000번 창구"라는 뜻이다. 보드 안의 cloudflared(터널 프로그램)가 http://localhost:5000으로 웹 서버에 붙는다.

2. Flask — 파이썬으로 만든 웹 서버

핵심 요약: Flask 멀티스레딩과 REST API를 결합하여 온디바이스 AI 추론의 웹 무선 원격 관제 환경 구축
Flask 가 뭔가?
파이썬으로 웹 서버를 쉽게 만드는 도구(라이브러리)다. "이 주소로 요청이 오면 이 함수를 실행해서 돌려줘"를 몇 줄로 적을 수 있다. 설치는 pip install flask. 
@app.route("/api/status")      # 이 주소로 요청이 오면
def api_status():              # 이 함수가 실행되고
    return jsonify(st)         # 상태를 JSON 으로 돌려준다
Flask 는 식당의 "주문 받는 규칙표"다. 메뉴(주소)마다 어떤 요리(함수)를 낼지 적어 둔다.
우리 서버에는 어떤 주소(창구)가 있나?
주소돌려주는 것
/보는 페이지(HTML). --team 이면 보드 4대를 한 화면에 보는 팀 화면
/me팀 모드여도 이 보드 자기 화면 (팀 모드일 때 휴대폰 알림을 누르면 여기로 온다)
/video_feed실시간 영상 (MJPEG, 아래 3장)
/api/status지금 상태를 담은 JSON (아래 4장)
/snapshot.jpg지금 한 장 사진
코드 확인: web.py 의 @app.route 다섯 개. 첫 버전 app.py 는 /, /video_feed, /api/status 세 개였다.
멀티스레딩은 뭐고, 왜 필요한가?
스레드는 프로그램 안에서 동시에 도는 "일꾼 한 명"이다. 멀티스레딩은 일꾼을 여러 명 두는 것. 영상 요청(/video_feed)은 끝나지 않는 요청이다. 브라우저가 창을 닫을 때까지 사진을 계속 보내야 한다. 일꾼이 한 명뿐이면 그 일꾼이 영상 보내기에 묶여서, 상태 요청이나 다른 사람의 접속을 받을 수 없다. 그래서 서버를 threaded=True 로 띄워 요청마다 일꾼을 따로 붙인다. 영상 보내는 일꾼, 상태 답하는 일꾼, 다른 사람 영상 보내는 일꾼이 동시에 일한다.
점원이 한 명이면 한 손님의 긴 주문(영상)을 처리하는 동안 다른 손님은 줄만 선다. 점원을 여럿 두면 동시에 받는다.
코드 확인: web.py 마지막의 self._app.run(host="0.0.0.0", port=self.port, threaded=True, ...). 웹 서버 자체도 추론 루프와 다른 스레드에서 돈다(threading.Thread(target=self._serve)). host="0.0.0.0" 은 "이 보드의 모든 네트워크 입구에서 요청을 받는다"는 뜻이라, 같은 네트워크의 다른 기기가 들어올 수 있다.
REST API 는?
API는 "프로그램끼리 대화하는 창구와 약속"이다. 사람이 보는 화면이 아니라 프로그램이 읽을 데이터를 주고받는다. REST는 그 창구를 만드는 흔한 방식으로, "주소 하나 = 정보 하나, 읽을 때는 GET 요청"처럼 웹 주소 규칙을 그대로 쓰는 것이다. 우리 것은 /api/status 주소에 GET 요청을 보내면 상태를 JSON 으로 돌려주는 단순한 형태다.
온디바이스 AI 추론, 웹 무선 원격 관제는?
온디바이스(On-device): AI 계산을 클라우드 서버가 아니라 기기(보드) 안에서 한다. 추론: 학습이 끝난 모델에 새 사진을 넣어 답(아기·칼 위치)을 얻는 것. 관제: 여러 곳의 상태를 한곳에서 지켜보고 관리하는 것. 원격: 떨어진 곳에서. 무선: 선 연결 없이 와이파이·휴대폰 데이터로. 즉 "보드 안에서 AI 가 판단하고, 그 결과를 멀리서 무선으로 지켜본다"는 말이다.

3. 영상 보내기 — MJPEG 서빙

01. 실시간 MJPEG 서빙 — OpenCV 프레임 캡처 후 /video_feed 엔드포인트를 통해 브라우저 무선 스트리밍
(v3 파일에서는 이 왼쪽 칸을 표·구조도와 겹쳐서 뺐다. 뜻은 알아 둘 것)
프레임, 프레임 캡처, OpenCV 는?
프레임: 영상을 이루는 사진 한 장. 웹캠은 1초에 30장(30 FPS)을 찍는다. 프레임 캡처: 카메라에서 그 사진 한 장을 꺼내 오는 것. OpenCV: 사진·영상을 다루는 유명한 라이브러리. 파이썬에서는 cv2 라는 이름으로 쓴다. 카메라 읽기, 박스 그리기, JPEG 로 압축하기를 여기서 한다.
MJPEG 는? 서빙은?
JPEG은 사진을 작게 줄여 저장하는 흔한 형식(.jpg)이다. MJPEG(Motion JPEG)은 JPEG 사진을 끊임없이 이어서 보내 영상처럼 보이게 하는 방식이다. 동영상 압축보다 단순하고, 브라우저가 <img> 태그 하나로 바로 보여 준다. 서빙(serving)은 "서버가 내어 준다"는 뜻이다. MJPEG 서빙 = MJPEG 영상을 내보내기.
파라파라 만화책. 한 장씩 빠르게 넘기면 움직이는 그림이 된다.
코드 확인: /video_feed 는 multipart/x-mixed-replace; boundary=frame 형식으로 응답한다. "여러 조각(multipart)을 보내는데, 새 조각이 오면 앞의 것을 바꿔 끼워라(replace)"라는 뜻이라 브라우저가 사진을 계속 갈아 끼운다. 압축 품질은 70. 보는 사람이 0명이면 JPEG 로 만들지도 않는다(저전력, if self.n_view > 0).
엔드포인트, 스트리밍은?
엔드포인트: 요청을 받는 주소 하나. /video_feed, /api/status 가 각각 엔드포인트다. (= 창구) 스트리밍: 다 받은 뒤 보는 게 아니라, 받는 즉시 흘려보내며 보는 것. 유튜브처럼.

4. 상태 보내기 — /api/status 와 1초 폴링

02. 상태 분리 비동기화 — 영상 전송과 별도로 /api/status REST API(1초 폴링)를 구축해 경합 방지
이 문장을 쉬운 말로 바꾸면?
"영상은 영상 창구로, 상태 정보(정상/주의/위험, 경보 횟수 등)는 상태 창구로 따로 보낸다. 화면은 1초마다 상태 창구에 '지금 어때?'라고 물어서 숫자와 배지를 바꾼다. 둘을 나눴기 때문에 영상 보내기와 상태 알려 주기가 서로를 기다리거나 부딪치지 않는다."
/api/status 는 무엇을 돌려주나? JSON 은?
JSON은 "이름: 값" 짝을 중괄호로 묶은 글자 형식이다. 사람도 읽을 수 있고 프로그램도 쉽게 읽는다. 우리 서버가 돌려주는 항목은 코드에서 확인한 대로 이렇다(값은 예시). 
{
  "status": "DETECTED",      // SAFE 정상 / DETECTED 주의 / DANGER 위험
  "alarm_cnt": 3,            // 지금까지 경보 횟수
  "fps": 4.8,                // 초당 처리 장수
  "led": "yellow",           // 화면의 LED 표시 (가운데 자리. 실제 보드 LED 는 파랑)
  "detections": [...],       // 지금 찾은 물체들 (이름·신뢰도·박스)
  "class_counts": {...},     // 종류별 개수
  "temp": 47.2,              // CPU 온도
  "model": "...",            // 모델·상태·클럭 한 줄
  "danger_info": "...",      // 위험 내용
  "logs": [...],             // 최근 위험 기록 30건
  "viewers": 1               // 지금 영상을 보는 사람 수
}
폴링(1초 폴링)은?
폴링(polling)은 "새 소식 있어?" 하고 정해진 간격마다 먼저 물어보는 방식이다. 우리 화면은 1초마다 /api/status 를 불러서 받은 값으로 배지·경보 횟수·FPS 를 바꾼다.
택배 조회 버튼을 1초마다 누르는 것. 서버가 먼저 알려 주는 방식(푸시)이 아니라 화면이 먼저 묻는다.
코드 확인: 화면 자바스크립트의 setInterval(poll, 1000) — 1000 ms(=1초)마다 poll() 을 실행하고, poll() 안에서 fetch('/api/status') 로 상태를 받아 온다. 팀 화면도 보드마다 1초마다 묻는다.
비동기(비동기화)는?
동기는 "답이 올 때까지 가만히 기다림", 비동기는 "물어 놓고 다른 일을 하다가 답이 오면 처리"다. 화면 코드는 async / await 로 상태를 묻기 때문에, 답을 기다리는 동안에도 영상이 멈추지 않고 시계도 계속 간다. "상태 분리 비동기화"는 결국 상태를 영상과 나누고, 따로(비동기로) 가져온다는 말이다.
경합 방지는 무슨 뜻인가?
경합은 여러 일꾼(스레드)이 같은 것을 동시에 쓰려고 다투는 것이다. 우리 코드에서 실제로 막고 있는 경합은 세 가지다.
무엇이 부딪칠 수 있나어떻게 막았나 (코드)
영상과 상태가 한 통로를 두고 서로 기다림주소를 /video_feed 와 /api/status 로 나누고, threaded=True 로 요청마다 일꾼을 따로 둠
추론 루프가 새 사진·상태를 쓰는 도중에 웹 일꾼이 반쯤 쓴 것을 읽음threading.Condition(잠금 장치)으로 쓰는 동안은 읽지 못하게 함 (with self._cv:)
첫 버전 app.py: 접속자마다 추론 루프가 하나씩 돌아, 두 명이 보면 같은 AI 모델을 동시에 호출web.py 는 추론 루프를 하나만 돌리고 최신 사진을 나눠 주기만 함. 몇 명이 봐도 추론은 한 번 (web.py 맨 위 설명)
화장실 문 잠금장치. 누가 쓰는 중이면 다음 사람은 기다린다. 그리고 화장실을 영상용·상태용 두 칸으로 나눠서 줄이 섞이지 않게 했다.
"경합 방지"라는 말은 팀원B님 원문이다. 위 표는 그 말을 우리 코드가 실제로 하는 일로 풀어 쓴 것이다. 발표에서는 "영상과 상태를 나눠서 서로 기다리지 않는다" 정도로 말하면 충분하다.

5. 표 읽기 — Before / Action / After

표의 세 칸은 무슨 뜻인가?
Before(로컬 단독): 고치기 전. "로컬 단독"은 보드 혼자서만(그 자리에서만) 볼 수 있었다는 뜻. Action(해결 조치): 한 일. After(웹 관제 성과): 결과. 포트폴리오의 트러블슈팅 틀(현상 → 해결 → 결과)과 같은 구조다.
첫 줄: 보드 직결 모니터 필수 → Flask 서버 통합 → PC·모바일 원격 관제
보드 직결 모니터 필수 / cv2.imshow GUI 한계 → Flask 서버 통합 / web.py MJPEG 서빙 → PC·모바일 원격 관제 / 무선 브라우저 실시간 확인
cv2.imshow: OpenCV 가 화면에 창을 띄워 사진을 보여 주는 함수. 우리 감지 코드도 웹 없이 켜면 cv2.imshow("baby-danger", frame) 로 창을 띄운다. GUI: 그래픽 화면(창·버튼)으로 된 사용자 화면. 이 방식은 보드에 HDMI 모니터를 직접 꽂아야만 보인다(보드 직결). 그래서 웹 서버(Flask)를 프로그램 안에 넣고(서버 통합), web.py 가 영상을 MJPEG 로 내보내게 했다. 이제 같은 네트워크(와이파이·유선)의 PC·휴대폰 브라우저에서 선 없이 본다. 바깥(휴대폰 데이터)에서는 6장의 터널로 본다.
둘째 줄: 터미널 콘솔 로그 → /api/status → 웹 UI 실시간 연동
터미널 콘솔 로그 출력 / UI 시각화 부재 → /api/status API / 1초 폴링 비동기화 → 웹 UI 실시간 연동 / 상태 뱃지 & 경보 카운트
터미널(콘솔): 명령어를 치는 검은 글자 창(MobaXterm 화면). 로그: 프로그램이 찍는 기록 글. 전에는 상태가 여기 글자로만 나왔다(UI 시각화 부재 = 보기 좋은 화면이 없었다). 이제 /api/status 를 1초마다 물어 웹 UI(웹 화면)에 상태 배지(정상=초록, 주의=노랑, 위험=빨강 점멸 딱지)와 경보 카운트(누적 경보 횟수)를 바로바로 보여 준다(실시간 연동).

6. 밖에서 보기 — Cloudflare 터널

03. 외부망 터널링 지원 — Cloudflare 연동으로 원격 모바일/외부망 브라우저 실시간 접속
왜 밖(휴대폰 데이터)에서는 그냥 안 열리나? 외부망·내부망은?
10.10.15.61 같은 주소는 교육장 네트워크 안(내부망)에서만 통하는 주소(사설 IP)다. 휴대폰 데이터는 바깥 인터넷(외부망)이라 이 주소를 찾아갈 수 없다. 공유기가 바깥 요청을 막고 있기도 하다.
회사 내선 번호(내부망)는 회사 밖에서 걸면 안 된다.
포트포워딩은? 왜 "불필요"가 장점인가?
포트포워딩은 공유기 설정에 "바깥에서 ○번 창구로 오면 안쪽 이 기기로 넘겨라"라고 규칙을 적는 것이다. 공유기 관리자 권한이 있어야 하고, 교육장·어린이집 공유기는 우리가 만질 수 없는 경우가 많다. 터널을 쓰면 이 설정이 필요 없다.
터널(터널링)은 어떻게 동작하나?
보드 안의 cloudflared 프로그램이 먼저 바깥의 Cloudflare 로 연결을 열어 두고, 그 연결을 통해 양쪽으로 데이터가 오간다. 바깥에서 공유기를 뚫고 들어오는 게 아니라 안에서 밖으로 나간 길을 되돌아 쓰는 것이라 공유기 설정이 필요 없다.
건물 안에서 밖에 있는 친구에게 먼저 전화를 걸어 두면, 그 통화로 서로 얘기할 수 있다. 친구가 건물 안으로 전화를 걸 방법이 없어도 된다.
Cloudflare 공식 문서: "cloudflared initiates an outbound connection through your firewall from the origin to the Cloudflare global network", "without a publicly routable IP address". 우리 보드에서는 cloudflared tunnel --url http://localhost:5000 로 켠다(run_demo.py 가 자동으로 켬).
Public Domain, 임시 주소, 로그인 없이, HTTPS 암호화는?
Public Domain: 누구나 인터넷에서 찾아갈 수 있는 공개 주소. 터널을 켜면 https://단어-단어-단어.trycloudflare.com 같은 주소가 생긴다. 임시 주소 · 로그인 없이: Cloudflare 계정 없이 무료로 쓰는 "Quick Tunnel"이라, 켤 때마다 주소가 바뀐다. 그래서 프로그램이 새 주소를 휴대폰 알림으로 보내 준다. 보안 HTTPS 암호화: 이 주소는 https 라 오가는 영상·상태가 암호화된다. 여기에 우리 접속 암호(?k=(접속 암호))를 더해, 주소만 알아서는 못 열게 했다.
한계: Cloudflare 문서상 Quick Tunnel 은 테스트·개발용이고 동시 요청 200개 제한이 있다. 원래 슬라이드의 "무제한 대역폭"은 확인되지 않아 "로그인 없이 임시 주소"로 바꿨다. 질문이 나오면 "시제품이라 무료 임시 터널을 썼고, 제품이면 계정 기반 터널과 인증을 붙인다"고 답한다.

Remote viewer = 멀리서 보는 사람. 휴대폰 브라우저(모바일 관제)든 관리자 PC(모니터링 = 지켜보기)든 같은 주소로 본다. 1초 주기 실시간 연동 = 앞의 1초 폴링으로 상태가 1초마다 맞춰진다는 뜻.

8. 발표 때 나올 만한 질문

여러 명이 동시에 보면 보드가 느려지지 않나?
추론은 한 번만 하고, 만든 JPEG 한 장을 보는 사람들에게 나눠 준다(web.py 구조). 보는 사람이 늘면 보내는 양은 늘지만 AI 계산은 늘지 않는다. 보는 사람이 없으면 JPEG 압축도 하지 않는다.
왜 동영상(H.264 등)이 아니라 MJPEG 인가?
MJPEG 는 사진을 이어 보내기만 하면 되어 구현이 단순하고, 브라우저가 별도 플레이어 없이 <img> 로 바로 보여 준다. 대신 동영상 압축보다 데이터가 많다. (데이터 양을 직접 재 보지는 않았다)
주소가 새면 아무나 보는 것 아닌가?
접속 암호(?k=)가 맞아야 열리고, 첫 접속 뒤에는 쿠키로 옮겨 주소창에서 지운다(캡처·방문기록에 암호가 남지 않게). 터널 주소도 켤 때마다 바뀐다. 다만 제품 수준 보안은 아니라서 향후 과제에 "인증 강화"가 있다.
Flask 는 같은 와이파이에서만 보이나? 누가 만들었나? Cloudflare 가 있으면 Flask 는 필요 없나? 보안은 어느 쪽이 좋나?

같은 와이파이에서만? — Flask 의 한계가 아니라 주소의 한계다. Flask 는 host="0.0.0.0" 으로 떠서 누구의 요청이든 받지만, 보드 주소 10.10.15.61 이 교육장 네트워크 안에서만 통하는 사설 IP 라 같은 네트워크(와이파이든 유선이든)의 기기만 찾아온다. 휴대폰 데이터에서는 못 찾아온다.

누가 만들었나 — 첫 Flask 웹 서버 app.py 는 팀원B님(py_codev1). 지금 쓰는 web.py 는 9/22 정보윤 교육장 PC 대화에서 클로드코드가 app.py 구조를 바꿔 새로 쓴 것(추론 루프 1개 + 최신 사진 나눠 주기)이고, 9/23 팀원B님 계정으로 팀 저장소에 올라갔다(대화 기록·git 이력 확인).

Flask (web.py)Cloudflare 터널
하는 일화면·영상(MJPEG)·상태(JSON)를 만들어 내준다바깥 인터넷에서 보드의 5000번 창구까지 길을 잇는다
없으면보여 줄 것이 없다네트워크 안에서만 보인다
보안에서 맡는 것접속 암호 확인(?k= → 쿠키)https 암호화(휴대폰 ↔ Cloudflare)
Flask 는 음식을 만드는 주방, Cloudflare 터널은 주방까지 오는 배달 길. 터널은 요청을 보드 안 http://localhost:5000(= Flask)으로 넘길 뿐이다.

보안 비교? — 비교 대상이 아니다. 교육장 안에서 http://10.10.15.61:5000 으로 열면 https 가 아니라 암호화되지 않고, 첫 접속 때 주소의 암호도 같은 네트워크에서 엿볼 수 있다. 터널 주소는 https 다. cloudflared ↔ Cloudflare 구간이 암호화된다는 문장은 이번에 문서에서 확인하지 못했다. 터널 주소+암호를 알면 누구나 열 수 있고, 무료 Quick Tunnel 은 문서상 테스트·개발용이라 향후 과제 "인증 강화"가 있다.

답할 문장: "Flask 는 화면과 영상을 만드는 서버이고, Cloudflare 터널은 밖에서 그 서버까지 오는 길입니다. 접속 암호는 저희 서버가 확인하고, 밖에서 접속할 때의 https 암호화는 Cloudflare 가 해 줍니다."
