    2. 반가산기 (half adder) p.2

    판서 "연산기, half Adder". 연산기 = 계산하는 회로. 반가산기는 1비트 두 개를 더한다. 판서 예: 0 + 1 = 1, 1 + 1 = 10(2진) → 합(sum) 0, 올림(carry) 1.

    abs (합)c (올림)판서
    0000"→ 초기값, 10nsec delay #10;"
    0110두 줄을 묶고 s = 1 에 밑줄 (둘이 다르면 1)
    1010
    1101c = 1 에 밑줄 (둘 다 1 일 때만)
    • 식: s = a ^ b = a ⊕ b (판서 "ExOR" = XOR) · c = a & b = a·b (AND)
    • 첫 줄 옆 "초기값, #10" = 표 한 줄이 시뮬레이션 한 칸. 첫 줄이 시작값이고, 다음 줄로 넘어갈 때마다 #10;(10 ns) 기다린다 → 6절 시나리오
    • Vivado 회로도: RTL_XOR(s_i), RTL_AND(c_i) 두 개뿐
    • "반"인 이유: 아랫자리에서 올라오는 올림을 받을 입력이 없다. 그것까지 받는 것이 전가산기(3절)
    module half_adder (
    input  a,
    input  b,
    output s,
    output c
);
    assign s = a ^ b;
    assign c = a & b;
endmodule
    내 HW1: adder.v 맨 아래 half_adder 가 위 코드와 같다.

    3. 전가산기 (full adder) p.3

    판서 "연산기 full_adder". 전가산기는 a, b 에 아랫자리 올림 Cin 까지 3개를 더한다. 판서 예(한 자리 세로셈): Cin 1 + a 1 + b 1 = 3 = 2진 11 → S = 1, 올림 1 은 왼쪽 자리로 넘어가 그 자리의 Cin 이 된다.

    a, b → U_HA1 → S1, C1  │  S1, Cin → U_HA2 → S, C2  │  C1, C2 → OR → C
    abCinS1
    = a⊕b    		C1
    = a&b    		C2
    = S1&Cin    		SC
    = C1|C2
    00000000
    01010010
    10010010
    11001001
    00100010
    01110101
    10110101
    11101011

    판서 표는 위 4줄(Cin = 0)에 C1, 아래 4줄(Cin = 1)에 C2 를 적었다(아래 칸 위에 "C2"). 위 표는 세 칸을 모두 채운 것이고, S · C 칸은 판서와 같다.

    • 식: S = (a ⊕ b) ⊕ Cin · C = (a & b) + C2, 여기서 C2 = (a ⊕ b) & Cin
    • 불 대수(0과 1만 쓰는 논리 계산)에서 + 는 덧셈이 아니라 OR, · 은 AND
    • Vivado 회로도: U_HA1, U_HA2(half_adder 상자 2개) + RTL_OR(c_i)
    • 인스턴스(instance, 실체화) = 이미 만든 모듈을 부품처럼 하나 꺼내 쓴 것. U_HA1 은 그 부품의 이름표(1일차 gates DUT 와 같은 문법)
    module full_adder (
    input  a,
    input  b,
    input  cin,
    output s,
    output c
);
    wire w_s1;        // 판서 S1
    wire w_c1, w_c2;  // 판서 C1, C2

    assign c = w_c1 | w_c2;

    half_adder U_HA1 (.a(a),    .b(b),   .s(w_s1), .c(w_c1));
    half_adder U_HA2 (.a(w_s1), .b(cin), .s(s),    .c(w_c2));
endmodule

    (사용자 adder.v 의 full_adder — 연결 줄을 한 줄로 줄이고 주석만 바꿈)

    내 HW1: 판서의 S1 · C1 · C2 가 코드의 w_s1 · w_c1 · w_c2 다.

    4. 4비트 덧셈기 — 리플 캐리 p.4

    • 판서 "4bit" 세로셈: 자리마다 세로로 더하고, 빨간 상자로 묶은 한 자리 = 전가산기(FA) 1개(동그라미 "FA"). 맨 오른쪽 자리의 올림 입력은 0, 위쪽 화살표는 올림이 왼쪽 자리로 넘어가는 것. (판서 숫자는 일부가 흐려 옮기지 않았다)
    • 그림 "Full_Adder4": 각 FA 에 아래로 (bn, an) 이 들어가고 위로 Sn 이 나온다. 올림 사슬은 아래와 같다
    Cin = 0 (접지) → FA1 → C1 → FA2 → C2 → FA3 → C3 → FA4 → C (최종 올림)
    • 접지(GND) = 0 V. 판서의 ≡ 모양 기호. 논리로는 0
    • 리플 캐리 가산기(RCA, Ripple Carry Adder) = 올림이 물결(ripple)처럼 아랫자리부터 한 칸씩 전달되는 덧셈기. 맨 윗자리 결과는 아랫자리 올림이 다 넘어온 뒤에야 정해진다
    • Vivado 회로도: U_FA1~U_FA4(full_adder 4개). 이때 포트는 1비트씩 a1~a4, b1~b4, cin, s1~s4, c — 10절에서 벡터로 바뀐다
    module full_adder_4 (
    input  [3:0] a,
    input  [3:0] b,
    input        cin,
    output [3:0] s,
    output       c
);
    wire w_c1, w_c2, w_c3;   // 판서 C1, C2, C3

    full_adder U_FA4 (.a(a[3]), .b(b[3]), .cin(w_c3), .s(s[3]), .c(c));
    full_adder U_FA3 (.a(a[2]), .b(b[2]), .cin(w_c2), .s(s[2]), .c(w_c3));
    full_adder U_FA2 (.a(a[1]), .b(b[1]), .cin(w_c1), .s(s[1]), .c(w_c2));
    full_adder U_FA1 (.a(a[0]), .b(b[0]), .cin(cin),  .s(s[0]), .c(w_c1));
endmodule

    (사용자 adder.v 의 full_adder_4 — 연결 줄을 한 줄로 줄이고 주석만 바꿈)

    내 HW1: 처음부터 벡터 포트 input [3:0] a + 비트 선택 .a(a[0]) 로 썼다. U_FA1 = 0번 비트(가장 작은 자리) … U_FA4 = 3번 비트, 내부 올림 w_c1~w_c3 = 판서 C1~C3. U_FA1 의 cin 은 상수 0 이 아니라 포트 cin. 1비트 FA 8개를 바로 잇는 것과 4비트 2개를 잇는 것의 비교(같은 회로로 합성됨)는 개념문답 X장.

    5. 테스트벤치 연결과 상수 표현 p.5

    4비트 변수와 포트 연결 p.5

    • reg [3:0] a, b; — 판서 "4bit", a · b 위에 각각 "4". [3:0] = 3번~0번 비트 4개. 왼쪽 3번이 가장 큰 자리(MSB), 0번이 가장 작은 자리(LSB)
    • 판서 .a1(a[0]) .a2(a[1]) .a3(a[2]) .a4(a[3]) — 모듈 포트 a1~a4(1부터)에 TB 변수의 비트 a[0]~a[3](0부터)을 하나씩 연결. 번호가 하나씩 밀려 있다

    상수 표현 — 비트수 ' 수체계 값 p.5

    판서: .cin(1'b0) → "상수 표현", 형식 "비트수 ' 수체계 값"(수체계 = 진법). 16진수는 "4'h 값", 10진수는 "8'd100" 예. (10진수 아래 '~10' 으로 끝나는 한 줄은 (판독 불가))

    쓰는 법읽는 법확인 (2026-10-02 xsim 실측)
    1'b01비트 · 2진(b) · 0cin 을 0 으로 고정 (판서)
    4'b1010 · 4'd10 · 4'ha4비트 · 2진 / 10진 / 16진셋 다 10
    8'd1008비트 · 10진 · 100 (판서)8'b01100100 = 8'h64

    진법 글자: b 2진 · d 10진 · h 16진 · o 8진. 가운데 ' 는 작은따옴표(Enter 왼쪽 키)로, `timescale 의 `(Esc 아래 키)와 다르다.

    값이 비트 폭보다 크면 위쪽 비트가 잘린다(실측: integer 300 을 8비트 reg 에 넣으면 44 = 300 − 256, 2 를 1비트 reg 에 넣으면 0).
    내 HW1 TB 의 a = i; b = j; 는 32비트 integer 를 8비트 reg 에 넣는 것인데, i · j 가 0~255 라 잘리지 않는다. cin = k; 도 k 가 0 · 1 이라 그대로 들어간다.

    6. 시뮬레이션 시나리오와 Radix p.6

    4비트 테스트벤치 전체 p.6

    `timescale 1ns / 1ps
module tb_adder ();
    reg  [3:0] a, b;
    wire [3:0] s;
    wire c;
    integer i, j;

    full_adder_4 DUT (         // 판서 "Instance"
        .a1 (a[0]),
        .a2 (a[1]),
        .a3 (a[2]),
        .a4 (a[3]),
        .b1 (b[0]),
        .b2 (b[1]),
        .b3 (b[2]),
        .b4 (b[3]),
        .cin(1'b0),
        .s1 (s[0]),
        .s2 (s[1]),
        .s3 (s[2]),
        .s4 (s[3]),
        .c  (c)
    );

    initial begin              // 판서 "Simulation Scenario"
        for (i = 0; i < 16; i = i + 1) begin
            for (j = 0; j < 16; j = j + 1) begin
                a = i;
                b = j;
                #10;
            end
        end
        $finish;
    end
endmodule

    화면보이는 것읽기
    위 (0 ~ 150 ns)a = 0 동안 b 가 0 → 15, s 도 0 → 15, c = 00 + b = b. b 는 10 ns 마다 바뀐다(판서 동그라미 0, 1, 2 … 15)

    내 HW1(8비트, 계산): a · b 0~255, cin 0~1, s 0~255, c 0~1. c 를 s 위에 붙여 9비트로 읽으면 0~511 (최대 255 + 255 + 1).

    7세그먼트와 BCD (예고) p.14

    • 7세그먼트 = 막대 LED 7개(+ 점 DP)로 숫자 8 모양을 만든 표시기. Basys3 에는 4자리("8.8.8.8.")
    • 판서: 표시기 그림의 오른쪽 자리에 동그라미, 그 아래 "0000". 핀은 AN0~AN3(자리 고르기)과 CA~CG · DP(막대 하나하나) — 8절 표
    • 판서 "BCD ⇒" 화살표가 CA~DP 쪽을 가리킨다. 옆에 0000 → 0 → 0, 1010 → 10 → a, 1111 → 15 → F 표와, 0~9 · a~F 를 7세그먼트 모양으로 그린 그림
    • BCD(Binary-Coded Decimal) = 10진수 한 자리(0~9)를 4비트 2진수로 적는 방식. 예: 25 → 0010 0101
    • → 4비트 값을 7세그먼트 글자 모양으로 바꿔 보여 주는 회로(디코더)를 다음에 만들 것으로 보임(추측)
    내 HW1 보드 사진에서 쓰지도 않은 7세그먼트가 "8.8.8.8." 로 켜져 있었다. 쓰지 않는 핀의 기본값은 풀다운(약하게 0 쪽으로 당김 — AMD UG908 비트스트림 설정 BITSTREAM.CONFIG.UNUSEDPIN 기본값 Pulldown)이고, Basys3 7세그먼트는 0 일 때 켜지는 방식(8절 출처)이라 그렇게 보인 것으로 추측(직접 확인은 안 함).
