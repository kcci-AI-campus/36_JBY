1. 분류에서 검출로 — 이번 주의 가장 큰 변화

04 폴더까지 하던 것과 뭐가 달라?
지금까지는 분류(Classification)였다. "이 사진이 가위냐 바위냐 보냐"에만 답했다. 그래서 손이 어디 있는지는 모델이 모르고, MediaPipe라는 별도 도구로 손을 먼저 찾아 잘라낸 뒤 모델에 넣었다. 이번 주는 검출(Object Detection)이다. YOLO 하나가 "무엇이" + "어디에"를 동시에 답한다.
분류 (04까지)검출 (05)
모델이 답하는 것종류 1개 (가위/바위/보)종류 + 위치 + 신뢰도, 여러 개 동시에
출력 모양(1, 3) — 확률 3개(1, 7, 2100) — 후보 2,100개 × 숫자 7개
손 찾기MediaPipe HandDetector 필요불필요. YOLO가 직접 찾는다
사진 여러 개면못 한다 (한 번에 하나)된다. 손 두 개면 박스 두 개
전처리손 잘라내기 + 흰 여백 정사각형letterbox (비율 유지 회색 여백)
후처리argmax 한 줄필터링 + NMS + 좌표 되돌리기 (약 40줄)
라벨(정답) 만들기폴더에 나눠 담기만사진마다 박스를 직접 그려야 한다
분류는 "이 사진, 한 단어로 말하면?"이고 검출은 "이 사진에서 찾은 것 전부, 위치까지 말해 봐"다. 그래서 검출 모델은 출력이 훨씬 복잡하고, 그 복잡한 출력을 사람이 읽을 수 있는 박스로 바꾸는 후처리 코드가 길어진다. EX_03이 170줄이나 되는 이유가 이것이다.
이 변화가 지난 시간 분석과 직결된다. 04 실습에서 한 프레임 52 ms 중 MediaPipe 손 검출이 20~25 ms로 가장 큰 병목이었다. 검출 모델은 그 단계 자체가 없다. 대신 모델 자체가 무거워진다. 둘 중 뭐가 빠른지는 19절에서 따진다.
YOLO가 뭐야?
You Only Look Once의 줄임말이다. 예전 검출 방식은 사진의 여러 위치를 하나씩 잘라 "여기 뭐 있나?"를 반복해서 느렸다. YOLO는 사진 전체를 한 번만 보고 격자마다 "여기에 뭔가 있나, 있다면 무엇이고 박스는 어디까지인가"를 한꺼번에 내놓는다. 그래서 빠르다. 2015년에 나온 뒤 버전이 계속 올라 지금 쓰는 것이 YOLO11이고, 그중 가장 작은 nano(n) 모델을 쓴다.
Fine-tuning(파인튜닝)이 뭐야? 전이학습이랑 같은 거야?
거의 같은 말이다. 남이 큰 데이터로 학습해 둔 모델을 가져와 내 데이터로 조금 더 학습시키는 것이다. 다만 뉘앙스가 조금 다르다.
전이학습 (EX_03 MobileNetV2, 03 폴더)파인튜닝 (이번 YOLO)
본체얼려 두고(trainable=False) 끝에 붙인 층만 학습전부 다시 학습한다 (출발점만 빌림)
학습되는 파라미터164,355개2,590,409개 전부

82장밖에 없는데 250만 개를 전부 학습시켜도 되는 이유는, yolo11n.pt가 이미 COCO 데이터셋(사진 12만 장, 80종류)으로 "물체의 윤곽과 위치를 찾는 법"을 배워 둔 상태라서다. 그 능력을 유지한 채 "가위·바위·보"라는 3종류만 새로 익히면 되므로 적은 데이터로도 된다. 학습 로그의 Transferred 451/499 items from pretrained weights가 "빌려온 가중치 451개를 옮겨 담았다"는 뜻이다.

2. 단어 사전 (먼저 읽기)

앞 노트들에 있던 단어(tflite, LiteRT, 양자화, PTQ, INT8, scale/zero point 등)는 뺐다. 이번에 새로 나오는 것만.
단어한 줄 뜻비유
Object Detection (객체 탐지)사진에서 물체의 종류와 위치를 동시에 찾는 것"찾아서 동그라미 쳐"
Bounding Box (BB, 경계 상자)물체를 감싸는 네모. 보통 [x, y, w, h] 또는 [cx, cy, w, h]로 표현사진 위에 친 네모
cx, cy, w, h박스의 중심 가로·세로 좌표와 너비·높이. YOLO는 중심 기준으로 낸다"한가운데가 여기, 크기는 이만큼"
x, y, w, h박스의 좌상단 좌표와 너비·높이. OpenCV의 NMS는 이 형식을 받는다"왼쪽 위 모서리가 여기"
Confidence score (신뢰도)"이게 진짜 그 물체일 확률". 0~1. 낮은 것은 버린다확신의 정도
IoU (Intersection over Union)두 박스가 얼마나 겹치는지. 겹친 넓이 ÷ 합친 넓이. 1이면 완전히 같고 0이면 안 겹침두 원의 교집합 비율
NMS (Non-Maximum Suppression)같은 물체에 박스가 여러 개 겹쳐 나올 때 점수가 가장 높은 것만 남기고 나머지를 지우는 것중복 신고 정리
letterbox사진 비율을 안 찌그러뜨리고 정사각형으로 만들려고 위아래(또는 좌우)에 회색 띠를 붙이는 것와이드 영화를 4:3 TV에 틀 때 생기는 검은 띠
mAP (mean Average Precision)검출 모델의 성적표. 0~1. 분류의 accuracy에 해당하지만 위치가 얼마나 정확한지까지 본다종합 점수
mAP50 / mAP50-95mAP50은 IoU 0.5만 넘으면 정답으로 쳐 준 점수(후하다). mAP50-95는 IoU 0.5~0.95를 평균 낸 점수(깐깐하다)합격선 낮게 / 높게
P (Precision, 정밀도)모델이 "있다"고 한 것 중 진짜 맞은 비율. 헛다리를 안 짚는가말한 것 중 맞은 비율
R (Recall, 재현율)실제 있는 것 중 모델이 찾아낸 비율. 놓치지 않는가있는 것 중 찾은 비율
UltralyticsYOLO를 만들어 배포하는 회사이자 파이썬 패키지 이름. yolo라는 명령어를 제공한다YOLO 제조사
COCO사진 약 12만 장, 물체 80종류짜리 대형 검출 데이터셋. yolo11n.pt가 여기서 미리 학습됐다검출계의 ImageNet
.pt 파일PyTorch 모델 파일. Ultralytics YOLO는 PyTorch로 학습하고 .pt로 저장한다. .keras에 해당PyTorch 완제품 상자
NCHW / NHWC사진 데이터를 메모리에 늘어놓는 순서. N=장수, C=채널(RGB), H=높이, W=너비. PyTorch는 NCHW, TensorFlow는 NHWC같은 짐, 다른 적재 순서
GFLOPs사진 한 장 처리에 필요한 연산 횟수(10억 회 단위). 모델이 얼마나 무거운지의 척도계산량 kg
anchor-free예전 YOLO는 미리 정해 둔 박스 후보(anchor)를 썼는데, YOLO11은 격자마다 직접 박스를 내놓는다틀 없이 바로 그리기
mosaic 증강사진 4장을 잘라 붙여 한 장으로 만들어 학습시키는 기법. 물체가 잘리고 작아진 상황에도 강해진다4분할 콜라주
tflite_runtimetflite만 돌리는 아주 가벼운 패키지. 이 예제는 ai_edge_litert 대신 이걸 쓴다(11절)구형 휴대용 재생기

줄뜻

P가 0.002인데 R이 0.667인 게 무슨 상태야?
아무 데나 박스를 마구 뿌리고 있는 상태다. 재현율(R)은 "실제 있는 것 중 찾아낸 비율"이라, 박스를 수백 개 뿌리면 그중에 우연히 맞는 것이 생겨 높게 나온다. 정밀도(P)는 "내가 말한 것 중 맞은 비율"이라 헛박스가 많으면 바닥이다. 학습이 진행되면서 P가 0.002 → 0.987로 오르는 것이 "헛소리를 줄여 간다"는 뜻이다.
P가 낮고 R이 높은 것은 "아무거나 다 신고하는 사람"이다. 놓치는 건 없지만 대부분 오보다. 반대로 P가 높고 R이 낮으면 "확실할 때만 신고하는 사람"이다. 둘 다 높아야 쓸모가 있고, 그걸 한 숫자로 합친 것이 mAP다.
mAP50은 0.995인데 mAP50-95는 왜 0.862야?
기준의 엄격함이 다르다. mAP50은 정답 박스와 50%만 겹쳐도 맞았다고 쳐 준다. mAP50-95는 50%, 55%, …, 95%까지 열 단계로 재서 평균한다. 95%를 요구하면 박스가 거의 정확히 포개져야 한다.
즉 "손이 있다는 것과 대략 어디인지는 거의 완벽하게 맞히지만(0.995), 박스 테두리를 픽셀 단위로 딱 맞히지는 못한다(0.862)"는 뜻이다. 손은 경계가 불분명한 물체라 사람이 라벨링할 때도 손목을 어디까지 넣을지 애매하다. 실습 목적으로는 0.995면 충분하다.

def letterbox(img, new_shape=(320,320), color=(114,114,114)):
    h, w = img.shape[:2]    
    nh, nw = new_shape
    r = min(nw / w, nh / h)

    new_w, new_h = int(w * r), int(h * r)
    resized = cv2.resize(img, (new_w, new_h))

    pad_w = nw - new_w
    pad_h = nh - new_h
    pad_x = pad_w // 2
    pad_y = pad_h // 2

    padded = cv2.copyMakeBorder(
        resized,
        pad_y, pad_y,
        pad_x, pad_x,
        cv2.BORDER_CONSTANT,
        value=color
    )

    return padded, r, pad_x, pad_y
줄뜻
def letterbox(img, new_shape=(320,320), color=(114,114,114)):사진을 비율을 유지한 채 320×320으로 만드는 함수. color=(114,114,114)는 남는 자리를 채울 회색. 이 숫자는 YOLO의 관례다.
h, w = img.shape[:2]원본 높이·너비. 320×240이면 h=240, w=320.
r = min(nw / w, nh / h)축소 비율. 가로 비율과 세로 비율 중 작은 쪽을 택한다. 그래야 양쪽 다 목표 안에 들어온다. 320×240이면 min(320/320, 320/240) = min(1.0, 1.33) = 1.0.
new_w, new_h = int(w * r), int(h * r)줄인 뒤 크기. 여기서는 320×240 그대로.
resized = cv2.resize(img, (new_w, new_h))실제로 줄인다. cv2.resize는 (너비, 높이) 순서로 받는다(배열 모양과 반대라 헷갈리는 곳).
pad_w = nw - new_w / pad_h = nh - new_h남는 공간. 320−320=0, 320−240=80.
pad_x = pad_w // 2 / pad_y = pad_h // 2절반씩 위아래(좌우)로 나눈다. //는 몫만 취하는 나눗셈. pad_y = 40.
cv2.copyMakeBorder(resized, pad_y, pad_y, pad_x, pad_x, …)위, 아래, 왼쪽, 오른쪽 순서로 테두리를 붙인다. 240 + 40 + 40 = 320 완성.
return padded, r, pad_x, pad_y중요: 만든 사진뿐 아니라 r, pad_x, pad_y도 함께 돌려준다. 나중에 모델이 낸 박스 좌표를 원본 사진 좌표로 되돌리려면 이 세 숫자가 필요하다(16절).
왜 그냥 320×320으로 늘리면 안 돼?
320×240을 그대로 320×320으로 늘리면 세로로 1.33배 찌그러진다. 학습할 때는 letterbox로 넣어 놓고 추론할 때 찌그러뜨려 넣으면 모델이 못 알아본다. 학습과 추론의 전처리는 반드시 같아야 한다는 원칙은 04 실습(BGR/RGB 문제)에서 이미 겪은 것과 같다.
와이드 영화를 옛날 4:3 TV에 틀 때 위아래 검은 띠를 넣는 것과 똑같다. 띠를 안 넣으면 배우가 홀쭉해진다. 회색(114)을 쓰는 이유는 검정(0)이 "진짜 어두운 물체"로 오해될 수 있어서다.
홀수 여백이면 1픽셀이 모자란다. pad_h가 81이면 pad_y는 40이 되고 240+40+40 = 320이 아니라 319×320이 되어 set_tensor에서 에러가 난다. 320×240과 640×480에서는 여백이 짝수라 문제가 없지만, 다른 해상도를 쓰면 터질 수 있는 자리다. 안전하게 고치려면 아래쪽 여백을 pad_h - pad_y로 준다.

23. 복습 체크리스트

  • 분류와 검출의 차이를 말할 수 있다. 검출이 왜 MediaPipe를 안 쓰는지
  • Bounding Box의 cx,cy,w,h와 x,y,w,h 차이, 왜 변환이 필요한지
  • 라벨 파일 한 줄 0 0.303 0.557 0.322 0.619를 읽을 수 있다
  • letterbox가 무엇이고, r·pad_x·pad_y를 왜 돌려주는지
  • 출력 (1, 7, 2100)에서 7과 2100이 각각 무엇인지, 2100 = 1600+400+100의 유래
  • NMS가 왜 필요한지, IOU_TH를 올리거나 내리면 어떻게 되는지
  • 좌표를 세 번 옮기는 과정(비율 → letterbox 픽셀 → 원본 픽셀)을 설명할 수 있다
  • NCHW와 NHWC의 차이, np.transpose(img, (0,3,1,2))가 하는 일
  • mAP50과 mAP50-95의 차이, 0.995와 0.862가 각각 무슨 뜻인지
  • P와 R의 차이, 학습 초반 P 0.002 / R 0.667이 어떤 상태인지
  • 파인튜닝과 전이학습의 차이 (전부 학습 vs 끝만 학습)
  • quantize=8과 quantize=w8a32가 04 실습의 무엇에 해당하는지
  • 세 tflite 모두 입출력이 float32라서 코드가 안 바뀌는 이유
  • 학습 로그에서 82 images, 0 backgrounds, 0 corrupt를 왜 먼저 보는지
