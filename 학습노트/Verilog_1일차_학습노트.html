    5. 첫 회로: gates 모듈 p.19–20

    회로와 진리표 p.19

    입력 a, b 두 개로 기본 논리 게이트 7개를 한꺼번에 만든다. 진리표 = 입력의 모든 경우에 출력이 무엇인지 적은 표.

    aby0
    AND    		y1
    NAND    		y2
    OR    		y3
    NOR    		y4
    XOR    		y5
    XNOR    		y6
    NOT a
    000101011
    010110101
    100110100
    111010010

    NAND·NOR·XNOR 은 각각 AND·OR·XOR 의 결과를 뒤집은(NOT) 것이다. 판서에서 ~(a & b) 의 ~ 에 "Not" 이라고 적혀 있다. XOR(배타적 OR) = 두 입력이 다를 때만 1.

    코드 p.20

    `timescale 1ns / 1ps
module gates (
    input  a,
    input  b,
    output y0,
    output y1,
    output y2,
    output y3,
    output y4,
    output y5,
    output y6
);
    assign y0 = a & b;     // a and b
    assign y1 = ~(a & b);  // a nand b
    assign y2 = a | b;     // a or b
    assign y3 = ~(a | b);  // a nor b
    assign y4 = a ^ b;     // a exor b
    assign y5 = ~(a ^ b);  // a exnor b
    assign y6 = ~a;        // not a
endmodule
    부분판서·설명
    `timescale 1ns / 1ps맨 앞 ` 는 작은따옴표가 아니라 grave accent(키보드 Esc 아래 키). Verilog Simulation 시간 단위. 앞 1ns = 동작 단위(#1 이 1 ns), 뒤 1ps = 해석(시뮬레이션) 정밀도
    input a,앞에 wire 가 생략돼 있다(input wire a). 크기를 안 쓰면 1 bit
    ( … );괄호 안 = 포트(입출력) 목록. 닫는 괄호 뒤 ; 빠뜨리면 p.16 오류
    assign연결한다(판서 "wire"). 위아래 순서가 없다 — 왜? HW 구성으로 배치되기 때문(7개 게이트가 동시에 존재)
    & | ^ ~AND, OR, XOR, NOT. 비트 하나하나에 대한 연산(비트 연산자)

    시간 단위와 주파수 p.20, 25

    시간10의 거듭제곱 (초)1 주기가 이 시간이면 주파수는
    1 s1001 Hz
    1 ms10-31 kHz
    1 µs10-61 MHz
    1 ns10-91 GHz
    1 ps10-121 THz

    주파수 = 1 ÷ 주기. Basys3 의 클럭은 100 MHz 이므로 한 주기는 10 ns 다.

    6. RTL 회로도와 Netlist p.21–22

    RTL ANALYSIS → Open Elaborated Design → Schematic 을 누르면 내 코드가 그림으로 나온다. 판서: 왼쪽 input(a, b), 가운데 사각형 = gates module, 오른쪽 output(y0~y6). 게이트 기호 아래 RTL_AND, RTL_OR, RTL_XOR, RTL_INV(INV = 인버터 = NOT).

    Netlist 창판서뜻
    Nets (9)→ wire선. a, b, y0~y6 아홉 가닥
    Leaf Cells (7)→ cell, RTL Logic부품. y0_i(RTL_AND) … y6_i(RTL_INV) 일곱 개

    Netlist = "어떤 부품(cell)들이 어떤 선(net)으로 연결됐는가" 목록.

    판서 p.22: 실제 칩 7404 Hex Inverter(NOT 게이트 6개가 든 14핀 IC) 그림과 칩 안의 Die(실리콘 조각), "Die size", 그리고 Design → Synthesis → Layout 흐름. 칩을 만드는 회사에서는 설계가 결국 실리콘 위의 배치(Layout)가 되고, FPGA 에서는 그 대신 이미 있는 칩 안의 자원에 배치한다.

    7. 테스트벤치 p.22–25

    테스트벤치 파일 만들기 p.23

    1. Sources + → ◉ Add or create simulation sources → Create File → tb_gates
    2. Simulation Sources → sim_1 아래 tb_gates 에서 마우스 오른쪽 → Set as Top (판서 "Top module for Simulation")

    판서 p.22: 파란 상자 test_bench (tb_gates) 안에 gates 를 넣고, 왼쪽에서 a·b 에 0/1 을 넣어 주고, 오른쪽 y0~y6 을 지켜본다.

    설계(gates)는 자동차, 테스트벤치는 자동차를 올려놓고 페달을 밟아 보는 검사대. 검사대는 칩에 들어가지 않는다.

    코드 p.24–25, 28

    `timescale 1ns / 1ps
module tb_gates ();
    reg  a, b;
    wire y0, y1, y2, y3, y4, y5, y6;

    gates DUT (
        .a (a),
        .b (b),
        .y0(y0),
        .y1(y1),
        .y2(y2),
        .y3(y3),
        .y4(y4),
        .y5(y5),
        .y6(y6)
    );

    // for simulation
    initial begin
        a = 0;
        b = 0;
        #1;  // delay 1nsec
        a = 1;
        b = 0;
        #1;
        a = 0;
        b = 1;
        #1;
        a = 1;
        b = 1;
        $stop;
    end
endmodule

    (p.28 화면 기준. 사용자 파일 tb_gates.v 에는 $stop 앞에 #1; 이 하나 더 있어서 마지막 a=1, b=1 결과도 파형에 남는다 — 사용자 주석 "뒤에 딜레이 안 주면 a=1, b=1 에 대한 결과는 못 봄")

    부분판서·설명
    module tb_gates ();시뮬레이션용 Test module. 포트가 없다(밖과 연결할 일이 없으니까)
    reg a, b;register 의 약자. "1 bit 자료형". 값을 Drive(넣어 줄) 수 있고, 값을 스스로 유지한다 → 입력을 넣어 주는 쪽(input drive)
    wire y0 …;연결용, metal line(칩 안의 금속 배선). 출력은 연결만 한다
    gates DUT ( … );gates = 설계 모듈 이름, DUT = 인스턴스(실체화) 이름. DUT = Design Under Test(시험 대상). 판서 "U(nit) U(nder) T(est)" 라고도 함
    .a (a)gates 모듈의 port 이름(.a)으로 내부 변수(a)를 연결할 때 쓰는 모양. 점 뒤가 모듈 쪽 이름, 괄호 안이 테스트벤치 쪽 이름
    initial begin … end판서 "초기화". 시뮬레이션 시작 때 한 번 위에서 아래로 실행. 안에서 하는 일은 두 가지: 값을 write(변경), 시간 Delay
    #1;# Number = Delay 시간. `timescale 1ns 이므로 #1 = 1 ns 기다림
    $stop;시스템 Task(이름이 $ 로 시작하는 시뮬레이터 내장 명령). 시뮬레이션을 멈춘다. 비슷한 것으로 $finish(끝낸다)
    Multiple Driven error p.24 — 한 선을 여러 곳에서 동시에 값을 넣으려 하면 오류. 판서 "물리적 허용되지 않음". 한쪽은 1, 다른 쪽은 0 을 밀면 실제 회로에서는 합선(쇼트)이 나기 때문. 그래서 입력은 reg 로 넣어 주고, 출력은 wire 로 연결만 한다.
    initial, #1, $stop 은 시뮬레이션에서만 쓰는 문법이다. 실제 칩에는 "1 ns 기다려라" 같은 부품을 만들 수 없어서 설계 파일(gates.v)에는 쓰지 않는다.

    8. 시뮬레이션 실행과 파형 p.26–28

    SIMULATION → Run Simulation → Run Behavioral Simulation. 창 세 개 p.26:

    창보이는 것
    Scope계층 구조: tb_gates 안에 DUT(gates), glbl(Vivado 가 자동으로 넣는 전역 모듈)

    파형 읽기 p.27: 0~1 ns 에 a=0,b=0 → 1 ns 마다 a·b 가 바뀌고, 그때마다 y0~y6 이 위 진리표대로 바뀐다. 신호 이름은 y0/AND 처럼 바꿔 두면 보기 쉽다.

    툴바 p.28

    버튼판서
    ▶ (Run All)run_all — $stop 이나 끝까지 돌린다
    ▶ 옆 숫자 칸 + 단위시간 단위 설정 — 그만큼만 더 돌린다
    ↻ (Relaunch)reLaunch: 다시 실행 — 코드를 고친 뒤 처음부터 다시

    9. 보드 핀 배치 (I/O Planning) p.29–31

    RTL 회로도를 연 상태에서 아래 창의 I/O Ports(Find Results)를 보면 포트마다 Package Pin(FPGA 의 몇 번 다리에 연결할지)이 비어 있고, I/O Std 가 default (LVCMOS18), Vcco 1.800 으로 돼 있다 p.29. 판서: SW0 → a, SW1 → b, LED → y.

    보드 회로도(Basys3 schematic) BANK 14 에서 스위치·LED 가 꽂힌 FPGA 핀을 찾아 p.30:

    포트보드 부품Package PinI/O Std
    aSW0V17LVCMOS33
    (Bank 14, Vcco 3.3 V)
    bSW1V16
    y0LD0U16
    y1LD1E19
    y2LD2U19
    y3LD3V19
    y4LD4W18
    y5LD5U15
    y6LD6U14

    판서: Package Pin = FPGA PIN 이름, Bank = region(핀 묶음), I/O Std = IO 전기적 특성. LVCMOS33 = Low Voltage CMOS 3.3 V. Basys3 의 이 핀들은 3.3 V 로 동작하므로 기본값 1.8 V 를 반드시 3.3 으로 바꾼다.

    이 표는 사용자 파일 gates.xdc 와 일치(9/30 확인) · Digilent 공식 Basys-3-Master.xdc(LED0 = U16)와도 일치

    저장 p.30–31: Ctrl+S (Save Constraints) → ◉ Create a new file, File type XDC, File name gates → Constraints 아래 gates.xdc (target) 가 생긴다. XDC = 핀 배치·클럭 같은 제약을 적는 파일(Xilinx Design Constraints).
