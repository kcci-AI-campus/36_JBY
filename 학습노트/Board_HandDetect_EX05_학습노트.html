1. 이 실습이 뭐야

한 줄로 뭘 하는 거야?
EX_04는 카메라 화면 전체를 모델에 넣었다. EX_05는 화면에서 손을 먼저 찾아, 손 부분만 잘라서, 학습 사진처럼 생기게 다듬은 뒤 같은 모델에 넣는다. 모델은 한 글자도 안 바뀌고, 모델에 들어가는 사진만 바뀐다.
EX_04는 시험지 전체를 한 번에 채점기에 넣는 것이고, EX_05는 답안 칸만 오려서 넣는 것이다. 채점기(모델)는 같은데 오려 준 쪽이 훨씬 정확하다.
왜 이게 효과가 있어?
모델이 배운 사진(EX_03의 RPS_Dataset)은 "회색 벽 + 손이 화면 가득 + 300×300 정사각형"이었다. EX_04에서 들어간 사진은 "캐비닛·얼굴 + 손은 구석 + 320×240 찌그러뜨린 것"이라 배운 것과 딴판이었다. EX_05는 손 둘레만 잘라내고 정사각형에 놓아, 모델이 배운 사진과 비슷한 모양으로 만들어 준다. 이렇게 입력을 손질하는 걸 전처리라고 하고, 실무에서 모델보다 전처리가 성능을 더 좌우하는 경우가 많다.
손은 누가 찾아?
구글 MediaPipe의 손 추적 모델이다. 우리가 학습시킨 게 아니라 이미 완성된 걸 가져다 쓴다. cvzone이라는 라이브러리가 MediaPipe를 두 줄로 쓸 수 있게 감싸 놓았고, 그게 HandDetector다. 즉 이 프로그램에는 모델이 두 개 돈다. ① MediaPipe(손 위치 찾기) → ② MobileNetV2(가위바위보 판정).

7. make_square_img 함수 (27~46줄)

잘라낸 손 사진은 직사각형인데 모델은 224×224 정사각형만 받는다. 그냥 resize로 찌그러뜨리면 손 모양이 변해서, 비율은 유지하고 남는 부분을 흰색으로 채우는 함수를 따로 만들었다. 학습 사진 배경이 밝은 벽이라 흰색으로 채운다.
27  def make_square_img(img):
28      ho, wo = img.shape[0], img.shape[1]
29      aspectRatio = ho/wo
30      # 흰색의 background 이미지 준비
31      wbg = np.ones((IMG_SIZE, IMG_SIZE, 3), np.uint8) * 255
32      if aspectRatio > 1: # portrait
33          k = IMG_SIZE/ho
34          wk = int(wo*k)
35          img = cv2.resize( img, (wk, IMG_SIZE))
36          img_h, img_w = img.shape[0], img.shape[1]
37          d = (IMG_SIZE - img_w) // 2
38          wbg [:img_h, d:img_w+d] = img
39      else: # landscape
40          k = IMG_SIZE/wo
41          hk = int(ho*k)
42          img = cv2.resize( img, (IMG_SIZE, hk))
43          img_h, img_w = img.shape[0], img.shape[1]
44          d = (IMG_SIZE - img_h) // 2
45          wbg [d:img_h+d, :img_w ] = img
46      return wbg
줄뜻
27 def make_square_img(img):잘라낸 손 사진 img를 받아 224×224 정사각형을 돌려주는 함수.
28 ho, wo = img.shape[0], img.shape[1]원래 높이(ho)와 너비(wo). 배열 shape은 (높이, 너비, 채널) 순서라 [0]이 높이.
29 aspectRatio = ho/wo높이÷너비. 1보다 크면 세로로 긴 사진.
31 wbg = np.ones((224, 224, 3), np.uint8) * 255흰 도화지. 224×224×3을 전부 1로 만든 뒤 255를 곱해 흰색. uint8은 사진과 같은 자료형이어야 나중에 붙일 수 있어서.
32 if aspectRatio > 1: # portrait세로가 길면 → 높이를 224에 맞추고 너비는 비율대로.
33 k = IMG_SIZE/ho배율. 예: 높이 150이면 224/150 = 1.49배.
34 wk = int(wo*k)새 너비 = 원래 너비 × 배율. 예: 90 × 1.49 = 134. int로 정수.
35 img = cv2.resize(img, (wk, IMG_SIZE))134×224로 줄이거나 키움. resize는 (너비, 높이) 순서라 (wk, 224).
36 img_h, img_w = img.shape[0], img.shape[1]바뀐 크기 다시 읽기. img_h는 224, img_w는 134.
37 d = (IMG_SIZE - img_w) // 2좌우 여백. (224 − 134) ÷ 2 = 45. 가운데 놓기 위한 시작 위치.
38 wbg[:img_h, d:img_w+d] = img흰 도화지의 세로 전체, 가로 45~179 칸에 손 사진을 붙여 넣는다. 좌우 45픽셀씩 흰 띠.
39 else: # landscape가로가 길거나 정사각형이면 → 너비를 224에 맞추고 높이는 비율대로. 위와 대칭.
40~42 k, hk, resize예: 160×100 사진이면 k = 224/160 = 1.4, hk = 140, 224×140으로.
43~45 d, wbg[d:img_h+d, :img_w] = imgd = (224 − 140) ÷ 2 = 42. 세로 42~181 칸, 가로 전체에 붙임. 위아래 42픽셀씩 흰 띠.
46 return wbg완성된 224×224 흰 배경 손 사진을 돌려준다.
사진을 액자에 넣는 것과 같다. 세로 사진은 좌우에, 가로 사진은 위아래에 흰 여백이 생긴다. 사진을 잡아 늘리지 않으니 손 모양이 그대로다.

48  def processImage(frame):
49      # 손 detect 시도
50      hands, _ = hd.findHands(frame, draw=False)
51      if not hands: return
52
53      # BB(Bounding Box) 얻기
54      x, y, w, h = hands[0]['bbox']
55
56      # 범위 초과 확인
57      if x<offset or y<offset or x+w+offset>320 or y+h>240: return
58
59      # BB의 좌상단 좌표 구하기 -> 좌와 상 방향으로 offset 만큼 늘림
60      x1, y1 = x-offset,  y-offset
61
62      # BB의 우하단 좌표 구하기 -> 우 방향으로만 offset 만큼 늘림
63      x2, y2 = x+w+offset, y+h
64
65      # 손만 떼어오기
66      img = frame[y1:y2, x1:x2]
67
68      # 떼어온 손을 정사각형으로 만들기
69      img = make_square_img(img)

48 def processImage(frame):EX_04와 같은 이름. 메인 루프가 매 프레임 부른다.
50 hands, _ = hd.findHands(frame, draw=False)MediaPipe 손 찾기. 찾은 손들의 목록(hands)과 그림이 그려진 사진을 돌려주는데, draw=False라 그림은 안 그리고 두 번째 값은 _로 버린다. 손 하나마다 박스, 관절 21개 좌표, 왼손/오른손 정보가 딕셔너리로 들어 있다.
51 if not hands: return손을 못 찾았으면 여기서 함수 끝. 아무것도 그리지 않는다. EX_04가 손 없어도 답하던 것과 결정적으로 다른 지점. 화면에 글자가 안 뜨면 이 줄에서 끝난 것.
54 x, y, w, h = hands[0]['bbox']첫 번째 손([0])의 박스. x, y는 왼쪽 위 모서리, w, h는 너비와 높이. 단위는 픽셀.
57 if x<offset or y<offset or x+w+offset>320 or y+h>240: return가장자리 검사. 박스를 30 넓혔을 때 화면(320×240) 밖으로 나가면 함수 끝. 네 조건은 순서대로 왼쪽·위·오른쪽·아래 여유 부족. 밖으로 나간 채 자르면 66줄에서 배열 범위 오류가 나기 때문에 미리 막는 것. 손을 화면 중앙에 두어야 하는 이유.
60 x1, y1 = x-offset, y-offset잘라낼 사각형의 왼쪽 위. 박스보다 왼쪽으로 30, 위로 30.
63 x2, y2 = x+w+offset, y+h잘라낼 사각형의 오른쪽 아래. 오른쪽으로 30 넓히고, 아래는 안 넓힌다. 아래쪽은 손목·팔이라 넣어 봐야 도움이 안 되기 때문. 주석의 "우 방향으로만"이 이 뜻.
66 img = frame[y1:y2, x1:x2]슬라이싱으로 손 부분만 오려낸다. 순서가 [세로, 가로]인 것에 주의. 결과는 직사각형.
69 img = make_square_img(img)7절 함수로 흰 배경 224×224 정사각형으로.
숫자로 한 번 따라가 보면?
MediaPipe가 박스 x=120, y=60, w=80, h=130을 줬다고 하자.
57줄: 120≥30, 60≥30, 120+80+30=230≤320, 60+130=190≤240 → 통과.
60줄: x1=90, y1=30. 63줄: x2=230, y2=190.
66줄: frame[30:190, 90:230] → 높이 160, 너비 140짜리 세로 사진.
69줄: 종횡비 160/140=1.14>1 → portrait. k=224/160=1.4, 너비 196으로 키움. d=(224−196)/2=14. 좌우 14픽셀 흰 띠가 있는 224×224 완성.
