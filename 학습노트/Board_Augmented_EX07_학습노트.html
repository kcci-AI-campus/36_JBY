1. 이 실습이 뭐야

한 줄로 뭘 하는 거야?
EX_05와 완전히 같은 코드로, 모델 파일만 EX_06(증강 학습)이 만든 것으로 바꿔 돌린다. 손 찾기·자르기·표시는 그대로이고, 판정하는 두뇌만 교체한 것. 그래서 EX_05와 나란히 돌려 보면 "모델만 바꾸면 얼마나 달라지나"가 순수하게 보인다.
같은 카메라, 같은 조명, 같은 손, 같은 절차로 시험을 보는데 채점관만 바꾸는 것. 점수 차이가 나면 그건 전부 채점관(모델) 차이다.
왜 코드를 안 바꾸고 파일 이름만 바꿨어?
비교 실험의 기본 원칙이다. 한 번에 하나만 바꿔야 결과 차이의 원인을 알 수 있다. EX_04→EX_05는 코드(입력 처리)만 바꿨고, EX_05→EX_07은 모델만 바꿨다. 둘을 한꺼번에 바꿨으면 뭐 때문에 좋아졌는지 모른다. 대학원 보고서에서 양자화 보정 방식 10종을 비교할 때도 다른 조건은 전부 고정했던 것과 같다.
.tflite 파일만 바꾸면 코드가 그냥 돌아가?
입력 모양(224×224×3)과 출력 모양(3개)이 같으면 된다. EX_03과 EX_06은 모델 구조가 완전히 같아서(파라미터 2,422,339개) 파일 크기까지 거의 같고, 안에 든 숫자(가중치)만 다르다. 코드는 파일을 열어 "입력 크기 얼마?"를 물어보고(16~18줄) 그에 맞춰 동작하니 이름만 바꿔도 된다. 나중에 04_Lightweighting의 INT8 모델은 자료형이 int8이라 조금 다르지만, 15줄에서 자료형도 파일에서 읽기 때문에 그것도 그대로 돈다.

27  def make_square_img(img):
28      ho, wo = img.shape[0], img.shape[1]
29      aspectRatio = ho/wo
30      wbg = np.ones((IMG_SIZE, IMG_SIZE, 3), np.uint8) * 255
32      if aspectRatio > 1: # portrait
33          k = IMG_SIZE/ho
34          wk = int(wo*k)
35          img = cv2.resize( img, (wk, IMG_SIZE))
36          img_h, img_w = img.shape[0], img.shape[1]
37          d = (IMG_SIZE - img_w) // 2
38          wbg [:img_h, d:img_w+d] = img
39      else: # landscape
40          k = IMG_SIZE/wo
41          hk = int(ho*k)
42          img = cv2.resize( img, (IMG_SIZE, hk))
43          img_h, img_w = img.shape[0], img.shape[1]
44          d = (IMG_SIZE - img_h) // 2
45          wbg [d:img_h+d, :img_w ] = img
46      return wbg

7. 48~91줄: processImage

48  def processImage(frame):
50      hands, _ = hd.findHands(frame, draw=False)
51      if not hands: return
54      x, y, w, h = hands[0]['bbox']
57      if x<offset or y<offset or x+w+offset>320 or y+h>240: return
60      x1, y1 = x-offset,  y-offset
63      x2, y2 = x+w+offset, y+h
66      img = frame[y1:y2, x1:x2]
69      img = make_square_img(img)
72      img = cv2.cvtColor(img,cv2.COLOR_BGR2RGB)
75      img = np.expand_dims(img, 0)
79      interpreter.set_tensor(input_details[0]['index'], img.astype(input_dtype))
81      interpreter.invoke()
83      output_data = interpreter.get_tensor(output_details[0]['index'])[0]
84      ans = np.argmax(output_data)
85      text = ansToText[ans]
88      cv2.rectangle(frame, (x1, y1), (x2, y2), colorList[ans], 2)
91      cv2.putText(frame,text,(x1,y1-7),cv2.FONT_HERSHEY_PLAIN,2,colorList[ans],2)

11. 왜 같은 코드가 다르게 동작하나

코드는 "사진을 준비해서 모델에 넣고 답을 받는" 절차일 뿐이고, 답을 정하는 건 모델 안의 숫자다. EX_05와 EX_07은 절차가 같고 숫자가 다르다.
상황기본 모델 (EX_03 학습)증강 모델 (EX_06 학습)
왼손 사진이 들어오면오른손만 배웠으니 엄지 위치가 반대인 낯선 모양. 헷갈림학습 때 50%는 뒤집힌 사진이었음. 익숙함
어두운 사진이 들어오면밝은 사진만 배움. 피부색 톤이 달라 헷갈림10~90% 밝기를 다 봤음
손이 치우친 사진중앙에 있는 손만 배움±10% 밀린 사진을 봤음
깨끗한 정면 오른손이 조건만 파서 100%98.9%. 조금 덜 정확
기본 모델은 "기출문제만 완벽히 외운 학생", 증강 모델은 "문제를 변형해 가며 풀어 본 학생". 기출 그대로 나오면 앞이 유리하고, 살짝만 바뀌어도 뒤가 유리하다. 웹캠 앞은 항상 "살짝 바뀐" 상황이다.

14. 복습 체크리스트

  • EX_05와 EX_07이 정확히 어느 줄이 다른지
  • 두 tflite 파일에서 같은 숫자와 다른 숫자가 각각 몇 개인지 (2,257,984 / 164,355)
  • 왜 한 번에 하나만 바꿔서 비교하는지 (통제 변인·조작 변인)
  • 왼손·어두움·구석·거리 각각이 EX_06의 어느 설정과 대응되는지
  • 기울인 손은 왜 둘 다 약한지
  • Colab 점수(100% vs 98.9%)와 보드 체감이 왜 반대인지
  • 모델 파일이 바뀌어도 코드가 그대로 도는 이유 (입출력 모양 같음, 15~17줄이 파일에서 읽음)
  • 10절 표를 실제로 채웠는지
