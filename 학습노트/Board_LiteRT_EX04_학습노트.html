1. 이 실습이 뭐야

한 줄로 뭘 하는 거야?
Colab에서 만든 RPS_MobileNetV2.tflite를 라즈베리파이에 올려서, 웹캠 영상을 실시간으로 가위/바위/보로 판정하는 프로그램이다. 학습은 없고 추론(inference)만 한다. 추론은 "학습 끝난 모델에 새 사진을 넣어 답을 받는 것"이다.
EX_03은 요리사를 교육시키는 과정(2분, GPU 필요), EX_04는 교육받은 요리사가 주문(사진)을 받아 요리(판정)를 내놓는 과정(초당 10~20번, 라즈베리파이 CPU로 충분).
LiteRT가 뭐고 왜 따로 있어?
구글의 경량 실행기. 옛 이름 TensorFlow Lite. Colab에서 쓴 TensorFlow는 학습까지 하는 큰 프로그램(수백 MB)이라 라즈베리파이엔 무겁다. LiteRT는 실행만 하는 작은 프로그램이고, 모델도 그에 맞춘 .tflite 형식을 쓴다. 파이썬에서는 ai_edge_litert라는 이름으로 불러온다. 보드의 install 폴더에 있던 tflite_runtime은 같은 것의 옛 이름이다.
EX_02(얼굴 검출)랑 뭐가 달라?
카메라 열기 → 반복해서 사진 찍기 → 처리 → 화면 표시 → q로 종료, 이 골격은 완전히 같다. 46~78줄은 EX_02와 한 글자도 다르지 않다. 다른 건 가운데 "처리" 부분뿐. EX_02는 OpenCV 내장 얼굴 검출기를 썼고, EX_04는 내가 만든 tflite 모델을 쓴다. 그래서 새로 배우는 줄은 7~44줄이다.

2. 단어 사전 (먼저 읽기)

단어한 줄 뜻비유
추론 (inference)학습 끝난 모델에 새 데이터를 넣어 답을 받는 것. Colab의 model.predict가 하던 일시험 보기 (공부 아님)
InterpreterLiteRT에서 .tflite 모델을 읽고 실행해 주는 객체. Keras의 model에 해당재생기
tensor (텐서)모델 안을 흐르는 숫자 배열. 입력 텐서 = 사진, 출력 텐서 = 확률 3개. numpy 배열과 같은 것이라고 봐도 된다컨베이어 위 상자
allocate_tensors텐서들이 쓸 메모리를 미리 잡아 두는 것. 모델 로딩 뒤 한 번만작업대 펼치기
input_details / output_details입력·출력 텐서의 정보 목록(이름, 번호, 모양, 자료형). 딕셔너리가 든 리스트투입구·배출구 설명서
index텐서의 번호표. set_tensor, get_tensor에 "몇 번 텐서"인지 알려줄 때 쓴다사물함 번호
dtype자료형. 이 모델은 float32(실수). INT8 양자화 모델이면 int8(정수)상자에 담을 수 있는 물건 종류
set_tensor → invoke → get_tensorLiteRT 추론 3단계: 입력 넣기 → 실행 → 출력 꺼내기. Keras predict 한 줄이 이 셋으로 풀린 것재료 넣기 → 버튼 → 꺼내기
expand_dims배열 앞에 차원 하나 추가. (224,224,3) → (1,224,224,3). 모델은 항상 "여러 장 묶음"을 받기 때문에 1장짜리 묶음으로 만든다사진 한 장을 봉투에 넣기
argmax배열에서 가장 큰 값의 위치 번호. [0.1, 0.8, 0.1] → 11등 번호 뽑기
VideoCaptureOpenCV의 카메라 객체. read()로 사진 한 장씩 꺼낸다카메라 리모컨
frame (프레임)영상의 한 장. 여기선 (240, 320, 3) 배열필름 한 컷
BGR / RGB색 순서. OpenCV는 파랑-초록-빨강, 모델은 빨강-초록-파랑으로 학습됨같은 색을 다른 순서로 적은 것
putText, rectangle사진 위에 글자·사각형 그리기사진에 펜으로 쓰기
waitKey키 입력을 잠깐 기다리는 함수. 창을 갱신하는 역할도 겸함잠깐 숨 고르기
FPS초당 프레임 수. 1초에 몇 장을 처리하나초당 처리 건수

7. processImage 함수 (24~44줄)

이 파일의 핵심. 사진 한 장을 받아 판정하고, 결과 글자를 사진 위에 쓴다. 메인 루프가 매 프레임 이 함수를 부른다.
24  def processImage(frame):
25      # BGR을 RGB로 변경
26      img = cv2.cvtColor(frame,cv2.COLOR_BGR2RGB)
27
28      # 모델의 입력 형태로 수정: (1,224,224,3)
29      # Normalization 처리 안함 (모델 내에서 -1 ~ 1로 변환 처리함)
30      img = cv2.resize(frame, (IMG_SIZE, IMG_SIZE))
31      img = np.expand_dims(img, 0)
32
33      # 모델에 입력하여 결과 얻기
34      #   input tensor 설정
35      interpreter.set_tensor(input_details[0]['index'], img.astype(input_dtype))
36      #   모델 실행
37      interpreter.invoke()
38      #   output tensor 얻기
39      output_data = interpreter.get_tensor(output_details[0]['index'])[0]
40      ans = np.argmax(output_data)
41      text = ansToText[ans]
42
43      # 판정 결과 표시
44      cv2.putText(frame,text,(180,50),cv2.FONT_HERSHEY_PLAIN,2,colorList[ans],2)
줄뜻
24 def processImage(frame):함수 정의. frame은 카메라에서 온 (240, 320, 3) 사진. 반환값은 없고, frame 위에 글자를 직접 쓴다(같은 메모리를 가리키므로 밖에서도 보인다).
26 img = cv2.cvtColor(frame, cv2.COLOR_BGR2RGB)BGR → RGB. 모델이 RGB로 학습됐기 때문(EX_03 7번 셀에서 COLOR_BGR2RGB를 했다). 결과를 img에 담는다.
30 img = cv2.resize(frame, (IMG_SIZE, IMG_SIZE))320×240 사진을 224×224로. 가로세로 비율이 안 맞아 약간 찌그러지지만 학습 때도 같은 방식이었다. 주의: 여기서 img가 아니라 frame을 넣었다. 아래 설명 참고.
31 img = np.expand_dims(img, 0)(224, 224, 3) → (1, 224, 224, 3). 모델은 "N장 묶음"을 받으므로 1장짜리 묶음으로. Colab에서는 test_data가 원래 (545, 224, 224, 3)이라 필요 없었다.
35 interpreter.set_tensor(input_details[0]['index'], img.astype(input_dtype))추론 1단계: 입력 넣기. 입력 텐서 번호(index)에 사진을 넣는다. astype(input_dtype)은 카메라 사진(uint8, 0~255 정수)을 모델 자료형(float32)으로 바꾸는 것. 값은 그대로 0~255. -1~1 변환은 모델 안의 preprocess_input이 한다(29줄 주석).
37 interpreter.invoke()추론 2단계: 실행. MobileNetV2 전체를 한 번 계산한다. 이 한 줄이 시간의 대부분을 먹는다. 라즈베리파이 CPU로 수십 ms.
39 output_data = interpreter.get_tensor(output_details[0]['index'])[0]추론 3단계: 출력 꺼내기. 출력 텐서는 (1, 3). [0]으로 묶음을 벗겨 (3,) = [가위 확률, 바위 확률, 보 확률]. 셋의 합은 1(softmax).
40 ans = np.argmax(output_data)제일 큰 확률의 번호. 0, 1, 2 중 하나.
41 text = ansToText[ans]번호를 이름으로. 'scissors' 등.
44 cv2.putText(frame, text, (180,50), cv2.FONT_HERSHEY_PLAIN, 2, colorList[ans], 2)원본 frame의 (x=180, y=50) 위치에 글자를 쓴다. 인자 순서: 사진, 글자, 위치, 글꼴, 크기 2배, 색(번호별), 굵기 2. FPS는 (20,50)에 쓰이니 같은 줄 오른쪽에 나란히 보인다.
30줄의 실수. 26줄에서 RGB로 바꾼 결과를 img에 담아 놓고, 30줄에서 크기를 줄일 때 img가 아니라 원본 frame을 넣었다. 그래서 26줄은 헛수고가 되고 모델에는 BGR 사진이 들어간다. 학습은 RGB로 했으니 빨강과 파랑이 뒤집힌 사진을 보는 셈이다. 손은 살색이라 큰 영향은 없을 수 있지만, 인식률이 떨어지는 원인 중 하나일 수 있다. EX_05에서는 cvtColor(img, …)로 순서가 바로잡혀 있다. 고치려면 30줄의 frame을 img로 바꾸면 된다.
왜 Colab에서는 predict 한 줄이었는데 여기선 세 줄이야?
Keras의 model.predict(x)는 "넣고 → 돌리고 → 꺼내기"를 안에서 다 해 주는 포장이다. LiteRT는 작게 만들려고 포장을 벗겨 세 동작을 따로 노출한다. 대신 입력 텐서를 미리 잡아 두고 매번 값만 갈아 끼우기 때문에 반복 실행이 빠르고 메모리도 적게 쓴다. 대학원 보고서의 NPU 코드도 같은 구조(입력 설정 → 실행 → 출력 읽기)였다.

17. 복습 체크리스트

  • 학습과 추론의 차이, 그리고 EX_03과 EX_04가 각각 어느 쪽인지
  • LiteRT가 왜 따로 있고, .tflite와 .keras 중 어느 쪽이 보드로 가는지

  • 30줄의 실수가 뭔지, 왜 결과에 큰 티가 안 나는지
  • EX_04 → EX_05 → EX_07이 각각 뭘 바꿔서 인식률을 올리는지 (입력 전처리 / 모델)
  • FPS가 왜 흔들리는지, 순간값과 평균값의 차이
