1. 왜 경량화를 하나

Colab에서 모델을 학습할 때는 구글의 GPU를 빌려 쓴다. 메모리도 넉넉하고 전기도 남의 것이다. 그런데 완성된 모델이 실제로 돌아갈 곳은 라즈베리파이 5다.

Colab (학습할 때)라즈베리파이 5 (추론할 때)
연산 장치GPU (T4·V100 등)CPU 4코어
메모리12~25GB4~8GB (OS와 공유)
저장 공간사실상 무제한SD카드 32GB
전력신경 안 씀USB-C 전원, 발열 주의
요구 속도몇 시간 걸려도 됨1초에 여러 장 처리해야 함

그래서 "정확도를 조금 내주더라도 작고 빠르게" 만드는 작업이 필요하다. 이게 경량화(lightweighting)이고, On-Device AI의 핵심 역량이다.

모델을 이삿짐이라고 보자. 창고(Colab)에 있을 때는 아무래도 상관없지만 원룸(라즈베리파이)으로 옮기려면 줄여야 한다. 방법이 셋이다. 안 쓰는 물건을 버리거나(Pruning), 비슷한 물건을 한 종류로 통일하거나(Clustering), 물건 하나하나를 작게 압축하는(Quantization) 것이다.

2. 단어 사전 (먼저 읽기)

단어뜻
가중치 (weight)모델이 학습으로 알아낸 숫자들. 모델 파일 크기의 거의 전부가 이 숫자 뭉치다. 이 장의 MNIST 모델은 약 5만 8천 개
Pruning (가지치기)값이 0에 가까운 가중치를 아예 0으로 만드는 것. 영향이 작은 연결을 끊는다
Sparsity (희소성)전체 가중치 중 0인 것의 비율. "sparsity 80%" = 10개 중 8개가 0
Clustering (군집화)비슷한 값의 가중치를 몇 개의 대푯값으로 통일하는 것. "16개 클러스터" = 그 층의 가중치가 16가지 값만 씀
Centroid (중심값·대푯값)클러스터를 대표하는 그 하나의 값
Quantization (양자화)숫자를 담는 그릇을 작게 바꾸는 것. float32(4바이트) → int8(1바이트)면 용량이 1/4
PTQPost-Training Quantization. 학습이 끝난 뒤 변환만으로 양자화. 간단하지만 정확도 손실이 클 수 있다
QATQuantization-Aware Training. 학습 중에 양자화를 미리 흉내 내며 훈련. 손해에 모델이 미리 적응해서 정확도가 덜 떨어진다
Representative datasetPTQ INT8에서 필요한 대표 데이터 100장. "실제 입력이 대략 어느 범위인가"를 재서 변환 비율을 정하는 데 쓴다
Scale / Zero point양자화 환산표의 두 값. 실수 ≈ scale × (정수 − zero_point). 정수를 실수로 되돌리는 환율이라고 보면 된다
TFMOTTensorFlow Model Optimization Toolkit. 이 장에서 쓰는 경량화 도구 묶음 (tensorflow_model_optimization)
strip_pruning / strip_clustering학습 중에만 필요했던 보조 장치를 떼어내는 함수. 이걸 해야 모델이 원래 구조로 돌아온다
LiteRT예전 이름 TensorFlow Lite. 보드처럼 작은 기기에서 모델을 돌리는 실행기. 파일 확장자가 .tflite
benchmark_model구글이 주는 측정 도구. .tflite 파일의 추론 시간을 재 준다
fine-tune (미세조정)이미 학습된 모델을 조금만 더 학습시키는 것. 경량화로 망가진 정확도를 회복시키는 데 쓴다

이 장에서 가장 헷갈리는 부분. Pruning과 Clustering은 파일을 직접 작게 만들지 못한다. 0이 많아지거나 같은 값이 반복될 뿐, 숫자의 개수도 그릇 크기도 그대로이기 때문이다. 그래서 .tflite 크기가 거의 같다. 이득은 zip으로 압축했을 때 나타난다 — 0과 반복값은 압축이 잘 되니까. 실제로 EX_03·EX_04 노트북에도 이렇게 적혀 있다. 
# 최종 clustered model의 구조 확인
# baseline model과 같음 : memory size에서도 달라진 부분이 없음 (TFMOT clustering 의 한계)
반대로 Quantization은 그릇 자체를 바꾸므로 파일이 진짜로 줄고 진짜로 빨라진다. 보드에 올릴 때 실제 효과를 보는 건 양자화 쪽이다.
Pruning·Clustering = 압축하면 이득 (전송·저장에 유리) / Quantization = 그 자체로 이득 (메모리·속도에 유리)

그럼 Pruning·Clustering은 왜 배우나

둘의 진짜 쓰임은 양자화와 함께 쓸 때다. 0이 많고 값 종류가 적은 모델을 양자화하면 더 잘 줄어든다. 그게 EX_09~EX_11의 결합 기법이고, 이 장이 이 순서로 짜인 이유다.

원본 모델→Pruning / Clustering→Quantization→.tflite→보드

test_images = (test_images / 255.0).astype(np.float32)

코드설명
mnist.load_data()손글씨 숫자 0~9 흑백 사진 7만 장을 자동으로 받아온다. 학습용 6만 장, 시험용 1만 장으로 이미 나뉘어 있다. 한 장은 28×28 픽셀
train_images / 255.0픽셀값이 0~255(정수)인데 이걸 255로 나눠 0~1 사이 소수로 만든다(정규화). 숫자 범위가 크면 학습이 불안정해지기 때문이다
.astype(np.float32)자료형을 32비트 실수로 고정. 나중에 양자화에서 "원래 몇 바이트였나"의 기준이 되는 게 이 float32다
np.expand_dims(..., axis=-1)모양을 (60000, 28, 28) → (60000, 28, 28, 1)로 바꾼다. 맨 뒤에 채널 축을 붙이는 것
채널 축이 왜 필요한가? Conv2D 층은 컬러 사진을 기준으로 만들어져서 "가로, 세로, 색깔 개수" 세 칸을 기대한다. 컬러는 RGB라 채널이 3, 흑백은 1이다. MNIST는 흑백이라 원래 채널 칸이 없으니 1을 억지로 끼워 넣어 모양을 맞춰 주는 것이다. 가위바위보 실습에서 (1,224,224,3)의 마지막 3이 이 자리다.

# ── EX_01: 새로 만들어 학습 ──
model = keras.Sequential([
    keras.Input(shape=(28, 28, 1)),
    keras.layers.Conv2D(filters=32, kernel_size=3, activation='relu'),
    keras.layers.MaxPooling2D(pool_size=2, strides=2),
    keras.layers.Conv2D(filters=16, kernel_size=3, activation='relu'),
    keras.layers.MaxPooling2D(pool_size=2, strides=2),
    keras.layers.Flatten(),
    keras.layers.Dense(128, activation='relu'),
    keras.layers.Dense(10, activation='softmax')
])

model.compile(optimizer='adam',
              loss=keras.losses.SparseCategoricalCrossentropy(),
              metrics=['accuracy'])

hist_base = model.fit(train_images, train_labels, epochs=10, validation_split=0.1)
model.save(save_dir + 'baseline_model.h5')
코드설명
Sequential([...])층을 일렬로 쌓은 모델. 위에서부터 차례로 통과한다
Input(shape=(28,28,1))입력 한 장의 모양을 알려 준다. 장수(60000)는 안 쓴다 — 몇 장이든 상관없기 때문
Conv2D(filters=32, kernel_size=3)3×3짜리 돋보기 32개로 이미지를 훑어 특징을 뽑는다. 세로선·가로선·모서리 같은 것을 각 돋보기가 하나씩 담당하게 학습된다
activation='relu'음수는 0으로, 양수는 그대로. 모델에 휘어짐을 주는 장치다. 이게 없으면 층을 아무리 쌓아도 직선 하나와 같아진다
MaxPooling2D(pool_size=2)2×2 칸에서 가장 큰 값만 남겨 크기를 절반으로 줄인다. 계산량을 줄이고 위치가 약간 달라져도 견디게 만든다
Flatten()2차원 격자를 한 줄로 쭉 편다. 다음의 Dense 층이 1차원만 받기 때문
Dense(128, 'relu')뉴런 128개짜리 완전연결 층. 앞 단계의 모든 값과 연결된다 — 그래서 가중치가 가장 많이 몰리는 곳이고, EX_02가 여기만 골라 가지치기하는 이유다

5. Pruning — 가지치기 (EX_01 · EX_02)

영향이 작은 가중치를 0으로 만드는 것. 나무에서 잔가지를 쳐내도 나무 모양은 그대로인 것과 같다.

회사에 직원이 1000명 있는데 그중 800명은 하는 일이 거의 없다고 하자. 그 800명을 해고하지 않고 책상에 그대로 두되 일은 안 시키는 게 pruning이다. 조직도(모델 구조)는 그대로라 건물 크기(파일 크기)는 안 줄어든다. 대신 명단을 적어 보내면 "없음, 없음, 없음…"이 반복돼서 압축이 잘 된다.

EX_01 — 모델 전체에 가지치기

batch_size = 128
epochs = 2
validation_split = 0.1

num_images = train_images.shape[0] * (1 - validation_split)
end_step = np.ceil(num_images / batch_size).astype(np.int32) * epochs

pruning_params = {
      'pruning_schedule': tfmot.sparsity.keras.PolynomialDecay(
                              initial_sparsity=0.50,
                              final_sparsity=0.80,
                              begin_step=0,
                              end_step=end_step)
}

model_for_pruning = tfmot.sparsity.keras.prune_low_magnitude(model, **pruning_params)
코드설명
batch_size = 128한 번에 128장씩 묶어서 학습한다. 6만 장을 한꺼번에 보면 메모리가 터지니 나눠 보는 것
num_images = 60000 × 0.9학습에 실제로 쓰는 장수. 10%는 채점용으로 빼 두므로 54,000장
end_step = ceil(54000/128) × 2총 몇 번 가중치를 고치게 되나를 계산한다. 54000÷128 = 421.875 → np.ceil로 올림해서 422, × 2에폭 = 844 스텝
PolynomialDecay(...)가지치기 일정표. "처음에는 50%만 자르고, 844번째 스텝에 가서 80%까지 서서히 늘려라"
initial_sparsity=0.50시작할 때 0으로 만들 비율 = 절반
final_sparsity=0.80끝났을 때 0인 비율 = 10개 중 8개
prune_low_magnitude(model, ...)low magnitude = 크기가 작은 것을 자른다는 뜻. 절댓값이 0에 가까운 가중치부터 0으로 만든다
**pruning_params딕셔너리를 펼쳐서 함수 인자로 넘기는 파이썬 문법. prune_low_magnitude(model, pruning_schedule=...)과 같다
왜 처음부터 80%를 안 자르고 서서히 늘리나? 한 번에 80%를 날리면 모델이 충격을 받아 정확도가 회복 불가능하게 떨어진다. 조금씩 자르면서 남은 가중치가 그 역할을 대신 배우도록 시간을 주는 것이다. 사람을 한꺼번에 내보내지 않고 단계적으로 줄이면서 인수인계를 시키는 것과 같다.

보조 장치 떼어내고 결과 확인

model_for_export = tfmot.sparsity.keras.strip_pruning(model_for_pruning)

total, non_zero = 0, 0
for l in model_for_export.layers:
    weights = l.get_weights()
    if len(weights)>0 and type(weights[0]) == np.ndarray:
        size = weights[0].size
        cnt_nonzero = np.count_nonzero(weights[0])
        total += size
        non_zero += cnt_nonzero
        print("[{:<10}] pruning rate : {}".format(l.name, (size - cnt_nonzero) / size))

print("Total parameter : {}".format(total))
print("Non-zero parameter : {}".format(non_zero))
print("Rate of pruned parmeter : {}".format((total-non_zero) / total))
코드설명
strip_pruning(...)반드시 해야 한다. 학습 중에는 "어느 가중치를 죽일지" 기록하는 마스크가 모델에 덧붙어 있다. 그 보조 장치를 떼어내 원래 구조로 되돌린다. 안 떼면 .tflite 변환이 실패하거나 파일이 더 커진다
for l in model.layers:층을 하나씩 돌면서

weights[0].size그 층의 가중치 총 개수
np.count_nonzero(w)0이 아닌 것의 개수
(size - cnt_nonzero) / size= 0인 비율 = sparsity. 0.8 근처가 나오면 성공
"{:<10}".format(...)왼쪽 정렬로 10칸 폭 맞춤. 출력이 표처럼 보이게 하는 것뿐
헷갈리기 쉬운 곳 — size - 가 있느냐 없느냐. np.count_nonzero는 이름 그대로 0이 아닌 것을 센다. 전체에서 그걸 빼야 0인 것이 남는다. 숫자를 넣어 보면 명확하다 — 가중치 10개 중 8개가 0인 경우:
식값뜻
size10전체 개수
cnt_nonzero20이 아닌 것의 개수
size - cnt_nonzero10 − 2 = 80인 것의 개수
(size - cnt_nonzero) / size8 / 10 = 0.80인 비율 = sparsity ✓

EX_01 결론: 정확도는 거의 유지, 0의 비율은 80%. 하지만 .tflite 파일 크기와 추론 속도는 거의 안 바뀐다. 이득은 zip 압축 비율에서만 나온다.
"그게 뭐가 좋은데?" — 정당한 의문이다. 이 실습만 놓고 보면 거의 쓸모가 없는 게 맞다. 이유는 라즈베리파이 CPU가 0을 0인 줄 모르고 0 × 3.7 = 0을 성실하게 계산하기 때문이다. 곱셈 횟수가 그대로니 안 빨라진다.
그래도 하는 이유가 셋이다. ① 실무 배포에서는 용량이 곧 전송비·시간 ② 양자화의 준비 단계(0이 많으면 양자화가 더 잘 먹는다 → EX_09~11의 존재 이유) ③ 조건만 맞으면 진짜로 빨라진다 — TFLite의 XNNPACK은 희소 추론을 지원해 80% 이상 0일 때 1.8~2.3배가 나오고(구글 미트 배경분리 모델 추론시간 30% 단축), NVIDIA Ampere 이후 GPU는 2:4 structured sparsity 전용 회로로 처리량 최대 2배·메모리 절반을 낸다. EX_01이 효과가 없는 건 조건이 안 맞아서다(XNNPACK은 1×1 합성곱 대상이고 PruneForLatencyOnXNNPack 정책이 필요한데, 여기서는 3×3 Conv에 일반 정책을 썼다).
그래서 이 실습은 "소프트웨어만으로는 여기까지가 한계다"를 보여주는 장치다. 0을 80% 만들어놨는데 아무 이득이 없는 이 상황이, 곧 AI 추론 가속기를 설계하는 이유다 — "0이면 계산을 건너뛰는 회로"를 만드는 것이 이 교육과정의 마지막 트랙이다. 자세한 설명과 출처는 개념문답_학습노트.html E장의 같은 제목 문답 참고.

EX_02의 진짜 목적 — 효율이 아니라 "부정적 영향 회피"다. 강사 설명은 "전체에 프루닝을 적용할 경우 발생할 수 있는 부정적 영향을, 일부 레이어에만 적용함으로써 피하기 위함"이다. 핵심은 층마다 프루닝을 견디는 힘이 다르다는 것. TensorFlow 공식 문서의 정확도 유지 지침이 이를 뒷받침한다.

왜 앞쪽 층은 프루닝에 약한가

① 중복(여유)이 없다. 첫 Conv 층은 돋보기가 32개뿐이고 각자 다른 특징(가로선·세로선·모서리)을 맡는다. 하나를 죽이면 그 특징은 아무도 안 본다. 반면 Dense(128)은 비슷한 일을 하는 뉴런이 여럿이라 하나 죽어도 옆에서 대신한다.
② 앞에서 잃은 정보는 뒤에서 못 되살린다. 신경망은 일방통행이다. 첫 층이 모서리를 못 뽑고 지나가면 뒤쪽 층이 아무리 똑똑해도 없는 정보를 만들어낼 수 없다. 뒤쪽 층은 앞에서 이미 좋은 특징을 뽑아 놨으므로 좀 흐려져도 견딘다.

이 결과에서 배울 것: 숫자를 볼 때는 먼저 "몇 장 차이인가"로 환산하고, 그다음 "출발점이 같았나"를 확인한다. 두 가지를 안 하면 노이즈를 성과로 착각하게 된다. 교수님 피드백이 요구하는 "구체적 수치"는 이 검증을 통과한 수치를 말한다.

6. Clustering — 군집화 (EX_03 · EX_04)

비슷한 값의 가중치를 몇 개의 대푯값으로 통일하는 것. 0으로 만드는 게 아니라 값의 종류 수를 줄인다.

페인트를 칠하는데 색을 1670만 가지 쓰고 있었다고 하자. 이걸 16색으로 줄여도 멀리서 보면 거의 똑같다. 대신 "이 칸은 3번 색" 식으로 번호만 적으면 되니 설명서가 짧아진다. 벽 크기(파일 크기)는 안 줄지만 설명서(압축 파일)가 줄어든다.

clustered_model = keras.models.clone_model(model, clone_function = apply_clustering_to_dense)

7. 양자화 · PTQ — 학습 후 양자화 (EX_05 · EX_06 · EX_07)

여기서부터 파일이 진짜로 줄고 진짜로 빨라진다. 가중치를 담는 그릇 자체를 바꾸기 때문이다.

자료형한 개당 크기표현 범위
float32 (원본)4바이트소수점 아래까지 아주 정밀
float162바이트정밀도 절반, 범위는 비슷
int81바이트−128 ~ 127 정수뿐
사진을 JPEG로 저장하는 것과 같다. 원본 RAW는 화질이 완벽하지만 크다. JPEG로 줄이면 자세히 보면 뭉개진 데가 있지만 눈으로는 거의 차이가 없고 용량은 1/10이다. 양자화는 모델에 하는 JPEG 압축이다. PTQ는 다 찍고 나서 압축, QAT는 찍을 때부터 압축될 걸 감안하고 찍는 것이다.

PTQ는 학습을 다시 하지 않는다. 변환기에 옵션만 붙이면 끝이라 가장 간단하다. 세 예제의 차이는 딱 그 옵션 줄뿐이다.

EX_05 — Dynamic Range (가장 간단)

converter = tf.lite.TFLiteConverter.from_keras_model(model)
converter.optimizations = [tf.lite.Optimize.DEFAULT]
tflite_model = converter.convert()
코드설명
converter.optimizations = [tf.lite.Optimize.DEFAULT]이 한 줄이 전부다. "알아서 최적화해라" = 가중치를 int8로 줄이라는 뜻

Dynamic Range라는 이름의 뜻: 가중치만 미리 int8로 바꿔 저장하고, 추론 중에 흐르는 중간 계산값(활성값)은 그때그때 상황을 봐서 변환한다. 미리 정해두지 않고 동적으로 범위를 잡는다는 의미다.

장점: 대표 데이터가 필요 없어 제일 쉽다. 파일은 약 1/4. 단점: 중간값 변환을 실행 중에 하므로 INT8 완전 양자화만큼 빠르지는 않다.

from_tensor_slices(train_images)학습 이미지를 한 장씩 꺼낼 수 있는 형태로 만든다
.batch(1).take(100)한 장씩, 100장만. 전부 넣을 필요 없다 — 범위만 알면 되니까

inference_input_type = tf.int8모델에 넣는 입력도 int8로 받겠다
inference_output_type = tf.int8나오는 출력도 int8로 주겠다
converter.representative_dataset = ...위에서 만든 공급 함수를 등록. 이게 없으면 INT8 완전 양자화는 불가능하다

['quantization']환산표를 꺼낸다. (scale, zero_point) 두 값이 들어 있다
scale정수 1칸이 실수로 얼마인가. 예: 0.0039면 int8 1칸 = 실수 0.0039
zero_point실수 0이 정수로 몇 번인가. 실수 범위가 0을 중심으로 대칭이 아닐 때 기준점을 옮겨 주는 값
환율과 같다. 실수 ≈ scale × (정수 − zero_point). "1달러 = 1350원"이 scale이고, "0원이 아니라 100원부터 시작"이 zero_point다. 이 두 값만 있으면 정수와 실수를 언제든 오갈 수 있으니, 모델 안에서는 정수로만 계산하고 입출력에서만 환전하면 된다. 정수 연산이 실수 연산보다 훨씬 빠르기 때문에 이게 속도 이득의 정체다.

8. 양자화 · QAT — 학습 중 양자화 (EX_08)

PTQ는 다 만든 뒤에 줄이는 것이라, 모델 입장에서는 갑자기 정밀도를 빼앗기는 셈이다. QAT는 학습할 때부터 "나중에 int8이 될 것"을 미리 알려 주고 훈련한다.

q_aware_model = tfmot.quantization.keras.quantize_model(model)

q_aware_model.compile(optimizer='adam',
              loss=keras.losses.SparseCategoricalCrossentropy(),
              metrics=['accuracy'])

q_aware_model.fit(train_images_subset, train_labels_subset,
                  batch_size=500, epochs=1, validation_split=0.1)

converter = tf.lite.TFLiteConverter.from_keras_model(q_aware_model)
converter.optimizations = [tf.lite.Optimize.DEFAULT]
tflite_model = converter.convert()

quantize_model(model)모델의 각 층 사이에 가짜 양자화 노드를 끼워 넣는다. 학습 중에 "실수 → int8 → 실수"를 왕복시켜 일부러 오차를 만든다
train_images_subset전체가 아닌 일부만 쓴다. 이미 학습된 모델을 적응시키는 것이라 조금이면 충분하고, 시간도 아낀다
epochs=1한 번만. 역시 fine-tune
optimizations = [Optimize.DEFAULT]변환 자체는 PTQ와 똑같은 한 줄이다. 차이는 "모델이 이미 양자화에 적응해 있다"는 것뿐
시력검사를 생각해 보자. PTQ는 맨눈으로 평생 살다가 갑자기 뿌연 안경을 쓰는 것이다. 처음엔 많이 헤맨다. QAT는 처음부터 그 안경을 쓰고 연습하는 것이다. 흐릿한 상태에 맞춰 눈이 적응했으니 실전에서 덜 틀린다.
같은 int8인데 QAT가 PTQ보다 정확도가 높다. 대가는 재학습 시간이다. PTQ는 몇 초면 끝나지만 QAT는 학습을 돌려야 한다.
가짜 양자화 노드는 학습용 장치다. quantize_model을 씌운 모델을 바로 저장하면 그 노드까지 딸려 간다. 그래서 반드시 .tflite로 변환해야 실제 int8 모델이 된다. pruning의 strip_pruning에 해당하는 단계가 QAT에서는 변환 그 자체다.

9. 결합 기법 — 지키면서 양자화 (EX_09 · EX_10 · EX_11)

이 세 예제가 존재하는 이유가 이 장의 핵심 통찰이다. 가지치기로 0을 80% 만들어 놓고 그 위에 그냥 QAT를 돌리면, QAT의 재학습이 그 0들을 다시 살려 낸다. 애써 만든 0이 사라지는 것이다. 군집화도 마찬가지로 16개로 묶어 둔 값이 다시 흩어진다. EX_10 노트북이 직접 이렇게 적어 두었다. 
* QAT  : training 과정에서 sparsity 파괴
* PQAT : training 과정에서도 sparsity 유지

그래서 "앞 단계에서 만든 성질을 깨지 않는 QAT"가 따로 필요하다. 이름이 그걸 그대로 말해 준다.

약자풀이무엇을 지키나예제

PQATPrune preserving QAT희소성(0의 자리)EX_10

이삿짐을 버리고(pruning) 종류별로 통일한 뒤(clustering) 압축팩에 넣는(quantization) 순서다. 그런데 압축팩에 넣는 과정에서 짐을 다시 풀어 헤치면 앞의 두 작업이 헛수고가 된다. "preserving"은 압축할 때 짐 구성을 건드리지 말라는 뜻이다.

세 예제의 공통 구조

EX_09·10·11은 전부 이 4단계를 따른다. 비교군을 일부러 같이 만드는 것이 특징이다.

def print_model_weights_sparsity(model):
    for layer in model.layers:
        for weight in layer.weights:
            if "quantize_layer" in weight.name:
                continue
            weight_size = weight.numpy().size
            zero_num = np.count_nonzero(weight == 0)
            print(
                f"{weight.name}: {zero_num/weight_size:.2%} sparsity ",
                f"({zero_num}/{weight_size})",
            )

def get_zipped_model_size(model):
  _, model_file = tempfile.mkstemp('.h5')

③ 정확도 — evaluate_model

.tflite는 케라스 모델이 아니라서 model.evaluate()를 못 쓴다. 직접 한 장씩 넣어 세어야 한다.

def evaluate_model(interpreter):
  input_index  = interpreter.get_input_details()[0]["index"]
  output_index = interpreter.get_output_details()[0]["index"]

  prediction_digits = []
  for test_image in test_images:
    test_image = np.expand_dims(test_image, axis=0).astype(np.float32)
    interpreter.set_tensor(input_index, test_image)
    interpreter.invoke()
    output = interpreter.get_tensor(output_index)
    digit = np.argmax(output)
    prediction_digits.append(digit)

  accurate_count = 0
  for index in range(len(prediction_digits)):
    if prediction_digits[index] == test_labels[index]:
      accurate_count += 1
  return accurate_count * 1.0 / len(prediction_digits)
코드설명
get_input_details()[0]["index"]모델의 입력 자리 번호. 인터프리터는 이름이 아니라 번호로 데이터를 주고받는다
np.expand_dims(test_image, axis=0)맨 앞에 축을 하나 붙여 (28,28,1) → (1,28,28,1). 모델은 항상 여러 장 묶음을 기대하므로 한 장이어도 "1장짜리 묶음"으로 만들어 준다. 4장 ③의 axis=-1(맨 뒤)과 헷갈리지 말 것
set_tensor(index, data)입력 자리에 데이터를 넣는다
invoke()추론 실행. 이 한 줄이 실제 계산
get_tensor(output_index)출력 자리에서 결과를 꺼낸다
np.argmax(output)10개 확률 중 가장 큰 것의 자리 번호. 그게 곧 예측한 숫자다
accurate_count / len(...)맞힌 개수 ÷ 전체 = 정확도
보드 예제 EX_04_Board_RPS_MobileNetV2.py의 processImage가 하는 일과 완전히 똑같은 4단계다. set_tensor → invoke → get_tensor → argmax. 입력이 MNIST 숫자냐 웹캠 손이냐만 다르다. LiteRT로 추론하는 방법은 어디서나 이 네 줄이다.

14. 복습 체크리스트

개념

  • Pruning·Clustering·Quantization이 각각 무엇을 줄이는지 한 문장으로 말할 수 있다
  • Pruning·Clustering이 .tflite 파일 크기를 왜 못 줄이는지 설명할 수 있다
  • PTQ와 QAT의 차이를 재학습 유무로 설명할 수 있다
  • PTQ INT8에 대표 데이터가 왜 필요한지 말할 수 있다
  • scale·zero point가 무엇이고 왜 필요한지 설명할 수 있다
  • CQAT·PQAT·PCQAT가 왜 따로 존재하는지 말할 수 있다

코드

  • strip_pruning·strip_clustering을 왜 해야 하는지 안다
  • UpdatePruningStep() 콜백의 역할을 안다
  • quantize_model과 annotate+apply의 차이를 안다
  • np.expand_dims(axis=-1)과 axis=0의 차이를 안다
  • LiteRT 추론 4단계(set_tensor→invoke→get_tensor→argmax)를 외운다
  • len(set(...))로 클러스터 수를, np.count_nonzero로 sparsity를 확인할 수 있다

실습

  • EX_01을 끝까지 돌려 baseline_model.h5를 만들었다
  • EX_05~EX_07을 돌려 파일 크기 세 가지를 비교해 봤다
  • EX_12로 가위바위보 INT8 모델을 만들어 보드에 올려 봤다
  • 보드에서 EX_13과 EX_15를 나란히 돌려 체감 차이를 확인했다
  • 13장의 비교표를 숫자로 채웠다
