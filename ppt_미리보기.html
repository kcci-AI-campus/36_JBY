4단계 상태 기계 — 실패하던 판정의 수정

READY ─SPACE→ COUNT(3초) ─0초→ JUDGING(유예 2초) ─손 2개→ RESULT(2.5초) → READY

· 문제 : 카운트 0인 "한 프레임"에서만 판정 → 11 FPS 환경에서 대부분 취소

· 해결 : JUDGING 유예 구간 2초 도입 → "0 이후 두 손이 처음 잡히는 프레임"으로 판정

· 결과 : 판정 취소 해소, 유예 안에 못 찾으면 Cancelled 안내 후 복귀 (3단계와 연결)

3. 핵심 기술

3-1. 분류에서 검출로 — 게임이 성립한 이유

검출 모델은 "무엇"과 "어디"를 함께 출력 → 두 손 동시 처리 가능

직접 구현한 후처리 3단계

① 신뢰도 필터 — 후보 2,100개 중 conf ≥ 0.4 만 통과

② NMS — 같은 손의 중복 박스 정리 (cv2.dnn.NMSBoxesBatched, IoU 0.45)

③ 좌표 복원 — letterbox(비율 유지 + 회색 114 여백) 좌표를 원본 해상도로 역변환

· 측정 결과 : 후처리 전체 0.36 ms/프레임 → 코드 길이와 실행 시간은 무관

이전 실습 (MobileNetV2 분류)본 프로젝트 (YOLO11n 검출)
모델 입력MediaPipe가 잘라낸 손 조각사진 전체 320×320
출력클래스 1개박스 후보 2,100개 → 필터 → 최종 박스
손 2개 처리불가가능 — 게임 성립의 전제
손 위치알 수 없음x 좌표로 P1/P2 구분
후처리없음 (argmax 1줄)약 40줄 (필터 → NMS → 좌표 복원)
