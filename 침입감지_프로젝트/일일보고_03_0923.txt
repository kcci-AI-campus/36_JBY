[3] 오늘 진행 업무
- 카메라 20 FPS 병목 해결 : 원인은 카메라 성능이 아니라 OpenCV 버퍼 크기였음.
  CAP_PROP_BUFFERSIZE가 1이면 한 장을 처리하는 동안 도착한 다음 프레임이 버려져
  전체의 1/3을 손실하고 있었음. 3으로 변경하여 20 -> 30 FPS 확보
  (속도 문제가 아니라 감시 공백 문제였음. 버려진 33ms 구간은 관측 불가)
- 검출 거리 문제의 원인 규명 : 1.5~2m 거리의 커터칼을 모든 모델이 0% 검출하던 현상을
  전날 "학습 데이터 부족"으로 결론지었으나 재검증 결과 오판이었음.
  실제 원인은 입력 해상도. 2m 거리의 15cm 칼은 입력 320에서 약 21픽셀에 불과
- 동일 가중치를 입력 크기만 320/640으로 재변환하여 통제된 비교 수행
  -> knife 검출률 0% -> 100%. 거리를 바꾼 4개 장면에서 모두 100% 재현
- 같은 장면을 한 번만 촬영해 모든 모델에 동일 프레임을 입력하는 비교 도구 작성
  (detect_rate.py). 모델마다 재촬영하면 대상 각도가 달라져 비교가 성립하지 않음
- 15개 모델 일괄 비교 결과, 팀 최종 데이터셋으로 재학습한 가중치(80epoch)가
  이전 가중치(120epoch)보다 오히려 열세 (knife 25% 대 100%)
- 실사용 기준 속도·전력 측정 (--seconds 옵션 추가, 벤치마크가 아닌 실제 실행 기준)
  입력 640 기준 FP32 7.5 FPS / INT8 21.1 FPS, CPU 89% 대 72%
- 저전력 기능 구현 : 기획 단계의 초음파 센서 기반 게이팅을 사용할 수 없게 되어
  동일 원리를 프레임 차분으로 구현. 직전 프레임과 픽셀 차이가 기준 미만이면
  추론을 건너뜀 (차분 1ms 대 추론 81ms)
- 전력 측정 수단 확보 : 라즈베리파이5 PMIC에서 전원 레일별 전압·전류를 읽어
  소비 전력(W)을 산출 (vcgencmd pmic_read_adc). 별도 전력계 없이 측정 가능
  측정이 추론 루프에 영향을 주지 않도록 별도 스레드에서 수집
- 게이팅 적용 결과 : 총 소비 전력 6.03W -> 2.26W (62% 감소),
  CPU 91% -> 7~16%, 온도 57.9도 -> 45.8도
- 외부 네트워크 접속 구현 : Cloudflare Tunnel을 이용해 보드가 외부로 먼저 연결을
  생성하는 방식으로 NAT 우회. 공유기 설정 권한 없이 LTE 환경에서 실시간 영상 확인
  터널 주소가 재시작마다 변경되므로 프로그램이 cloudflared에 직접 조회하도록 자동화
- 접속 보안 : --web-token 적용 및 토큰을 쿠키로 이전하여 주소창에 노출되지 않도록 처리
- 3색 LED 상태 표시 구현 (초록=정상 / 파랑=아기 감지 / 빨강=경보) 및 동작 확인
- 팀원 작성 웹 UI를 본 시스템에 통합 (클래스별 감지 현황, 침입 기록, LED 표시 패널)
- 팀 공유용 코드 패키지 및 GitHub 제출용 자료 정리

[4] 문제점 및 검토 필요 사항
- 오검출(false positive)을 아직 수치로 측정하지 못함. 책을 knife 46%, 의류를
  outlet 45%, 인체 일부를 knife 71%로 검출하는 사례를 육안 확인하였으나
  검출률만 측정하고 오검출률은 측정하지 않은 상태. 임계값 확정이 불가능
- 최종 데이터셋 재학습 모델(80epoch)의 성능 저하 원인 미규명. 에폭 수와 데이터셋이
  동시에 변경되어 변수가 2개임. 다만 체크포인트 해시 비교 결과 100epoch와
  120epoch 가중치가 동일하여 100epoch에서 수렴한 것으로 확인됨
  -> 동일 데이터로 100epoch 재학습 시 원인 구분 가능
- 저전력 수치의 절대값 신뢰도 : PMIC가 메인 5V 레일의 전류를 측정하지 못해
  USB 카메라 소비분이 합계에서 누락되었을 가능성이 있음. 조건 간 차이 비교로만 사용 중
- 시중 제품 대비 전력 우위는 성립하지 않음을 확인 (상용 AI 홈캠 2~2.7W로 동등 수준).
  본 시스템의 차별점은 전력이 아니라 두 객체 간 거리·체류 시간 기반의 위험 판정임

[5] 이전 문제점 해결 내용
- (9/22 미해결) 카메라가 20 FPS로 제한되던 문제
  -> 원인은 버퍼 크기 설정. 노출·USB 대역폭·카메라 사양을 순차적으로 배제한 뒤
     프레임 간격 히스토그램이 1배·2배 주기에 집중된 것을 근거로 프레임 손실로 판단.
     CAP_PROP_BUFFERSIZE를 3으로 변경하여 30 FPS 확보
- (9/22 미해결) 검출 거리가 짧아 실사용이 어렵던 문제
  -> 입력 해상도 문제로 규명. 640 재변환으로 knife 검출률 0% -> 100%
- (9/22 미해결) 640 입력 시 7.5 FPS로 실시간 처리 불가
  -> INT8 양자화로 21.1 FPS 확보. 본 프로젝트에서 INT8은 저전력 수단이 아니라
     640 입력을 실시간으로 사용하기 위한 필수 조건임을 확인
- (9/22 미해결) 경보 판정이 연속 검출을 요구하여 중간에 한 프레임만 놓쳐도 초기화되던 문제
  -> 최근 0.5초 중 60% 이상 조건으로 변경. 한 번의 실행에서 두 방식을 동시에 계산하도록
     구현하여 동일 프레임 기준 비교 확보. 실측 결과 연속 방식 3회, 비율 방식 4회로
     연속 방식이 경보 1회를 누락 (위험 상태 중 검출 단절 8회 발생)
- (9/22 미해결) 경보 알림 전송 중 예외 발생 시 프로그램 전체가 종료되어
  웹 접속까지 끊기던 문제 -> 알림·영상 전송부를 예외 처리로 분리하여 감시는 계속되도록 수정
- (9/22 미해결) 경보 영상이 실제보다 2.8배 빠르게 재생되던 문제
  -> 저장 프레임률을 고정값이 아닌 실측 FPS로 변경
- (9/22 미해결) 팀원 파일과 모델 파일명이 충돌하여 덮어쓰기가 발생한 문제
  -> 작성자·학습·정밀도·입력크기를 파일명에 포함하는 규칙을 정하고 팀에 공유

[6] 잔여 미해결 문제점 내용
- 오검출률 미측정 (칼·인형을 제거한 상태에서의 knife/outlet 검출률).
  이 수치가 없어 신뢰도 임계값(CONF_TH)을 확정하지 못하고 있음
- 기울어진 칼(45도, 수직, 역방향)에 대한 검출률 미측정. 팀 보완사항으로 접수된 항목
- outlet 클래스는 촬영 및 측정을 아직 수행하지 못함
- 거리별(0.5 / 1 / 1.5 / 2m) 검출률 표 미작성 -> 유효 감시 거리 미확정
- 최종 사용 모델 미확정 (입력 크기, 정밀도, 임계값)
- 외부 접속 인증이 토큰 방식이라 링크 전체가 유출되면 차단 불가.
  Cloudflare Access 등 계정 기반 인증은 도메인이 필요하여 현재 적용 불가
- 야간(적외선) 환경 미지원
