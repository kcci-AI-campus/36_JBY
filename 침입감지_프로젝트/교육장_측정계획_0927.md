# 교육장 장면별 전력 측정 계획 (2026-09-27 실행 예정)

목적: "어떤 장면에서 얼마나 절감되나"를 장면 4개 × 방식 3개 표 한 장으로 만든다. 발표 3-3(정보윤)·3-2(팀원A)·4(결과 분석) 공통 자료.

| 장면 | ① 게이팅 끔 (우리 코드) | ② 게이팅 켬 (우리 코드) | ③ 두 모드 (팀원A) | ④ 두 모드 + 게이팅 |
|:---|---:|---:|---:|---:|

굵은 "영상 근사"와 "없음"이 내일 채울 칸이다. A 는 다시 잴 필요 없다.

예상(측정 전 가설, 확인용): C(아기 움직임, 위험물 없음)는 세 방식 모두 4 W 안팎으로 모일 것이다. 두 모드는 "아기+위험물이 함께 안 보이면 3초 뒤 대기" 규칙 때문에 대기 5초 ↔ 고성능 3초 왕복(B 와 같은 4.2 W)이 되고, 게이팅은 움직임이 있으면 건너뛰지 못한다. 1.8 W 는 B(가만히)에서만 나온다. 이 가설이 맞으면 발표에서 "절감은 아기가 없거나 가만히 있을 때, 움직이거나 위험할 때는 일부러 안 줄인다" 로 말한다.

## 내일 할 측정 (각 60초, 화면 없이, 모두 실제 카메라·실물 인형·칼)

준비: 보드 `~/work/baby/` 에 우리 코드, `~/work/baby/anseong/` 에 팀원A 코드 두 모델. 카메라 고정, 조명 고정. 장면마다 아래 명령을 순서대로 돌린다. B·C·D 세 장면 × ③④⑤ 세 방식 = 9회가 필수, ①② 는 시간 남으면(총 약 20분). `detect_baby_3state.py` 는 교육장 보드에 아직 없으므로 GitHub `py_codev2/docs/보드실측_0926/3상태/` 에서 받아 `~/work/baby/anseong/` 에 넣는다.

```bash
source ~/work/env/bin/activate
# ② 우리 코드, 게이팅 켬
cd ~/work/baby && python3 detect_baby.py yolo11n_512.tflite --no-gui --seconds 60 --gate
# ① 우리 코드, 게이팅 끔 (B~D 는 이미 9/23 값이 있으니 시간 없으면 생략)
cd ~/work/baby && python3 detect_baby.py yolo11n_512.tflite --no-gui --seconds 60
# ④ 팀원A 두 모드 + 게이팅  (③ 은 --gate 만 뺀다)
cd ~/work/baby/anseong && python3 detect_baby.py --no-gui --seconds 60 --gate --power-csv 장면이름_gate
# ⑤ 3상태 판 (감시 상태 추가, 게이팅 기본 켬) — 9/26 밤 추가
cd ~/work/baby/anseong && python3 detect_baby_3state.py --no-gui --seconds 60 --power-csv 장면이름_3state
```

장면 만들기
- B: 인형을 카메라 앞에 두고 아무도 안 움직인다. 칼·콘센트는 화면 밖.
- C: 한 사람이 인형을 천천히 계속 움직인다(왔다 갔다). 칼·콘센트는 화면 밖.
- D: 인형을 칼 옆에 붙여 둔다(경보 계속). 알림 폭주가 싫으면 `--notify` 를 뺀다.

기록할 것: 종료 요약의 "평균 W", "CPU 평균", "실제 추론/건너뛴 프레임"(②·④), 팀원A 코드는 `*_summary.csv` 의 모드별 평균 W. 온도도 같이 적는다(5분 이상 연속 측정 시 발열로 값이 오른다 → 장면 사이 1분 쉼).

## (9/27 저녁 추가) 월요일 순서 — 저전력 실험을 실물로 확인하는 것까지

준비물: 인형, 커터칼, 콘센트(가능하면), 줄자. 보드에 올릴 파일: `저전력_실험_0927/detect_baby_4state.py`, `run4.sh`, GitHub `5-model/yolo11n/yolo11n_int8.tflite`, `model/yolo11n_640.tflite`(팀원B 640 FP32). 보드의 `~/work/baby/anseong/` 에 넣는다. 총 소요 약 1시간.

※ 설정 C 는 `sudo` 가 비밀번호 없이 되어야 클럭을 바꾼다(교육장 보드 확인). 끝나면 클럭은 자동 복구된다.

## (9/27 저녁 추가) 소등 시험 — 어두우면 검출이 되나 (향후 과제 '야간' 의 근거 숫자)
- 목적: "일반 웹캠은 빛이 없으면 검출이 안 된다" 를 숫자로 남긴다 (발표 4장 부족한 점 ②, 5장 향후 과제).
- 방법: 인형과 칼을 시연 거리(1.5~2 m)에 두고 ① 불 켠 상태 10초 ② 불 끈 상태 10초 ③ 스마트폰 손전등만 켠 상태 10초를 `python3 detect_baby.py <640 모델> --seconds 10 --no-gui` 로 돌린다. 요약 출력의 클래스별 검출 프레임 수(baby / knife)와 FPS 를 적는다.
- 기록 표: | 조명 | baby 검출 프레임 / 전체 | knife 검출 프레임 / 전체 | 비고 | 세 줄.
- 예상: 소등 시 0회. 손전등 부분 조명에서 얼마나 회복되는지가 "적외선 LED 만 있으면 되는가" 의 힌트.
