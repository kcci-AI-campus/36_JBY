[3] 오늘 진행 업무
- 프로젝트 주제 확정 : 저전력 온디바이스 AI 기반 위험구역 침입 감지 시스템
  (아기 인형이 콘센트·칼 등 위험물에 접근하면 LED 및 경보로 알리는 시스템)
- 검출 클래스 4종 정의 : baby / adult / knife / outlet
- 사용 부품 제한 통보 반영 : 초음파·적외선 센서 및 부저 사용 불가로,
  트리거를 카메라 프레임 차분으로 대체하고 출력은 LED·음성으로 설계 변경
- 담당 분담 : 본인은 outlet(콘센트·멀티탭) 데이터 담당
- 데이터 촬영 227장 → 품질 검수 후 190장 선별
  (흔들림·대상 미포함 등 37장 제외)
- LabelImg로 190장 라벨링(YOLO 형식), train 152 / test 38 분할 후 팀 드라이브 공유
- 팀원 데이터 병합 : 총 588장(train 455 / val 133), 박스 616개
  (baby 250 / knife 154 / outlet 212)
- Colab에서 YOLO11n 학습 (입력 640, 100 epoch, seed 고정), Tesla T4 기준 16분 소요
- 학습 결과 : 정밀도 0.991 / 재현율 0.980 / mAP50 0.980 / mAP50-95 0.872
  클래스별 mAP50 - baby 0.995, knife 0.965, outlet 0.978
- LiteRT(tflite) 변환 3종 생성 : float32 / INT8 / w8a32 (입력 320)
- 라즈베리파이 보드용 추론 코드 작성
  (검출 → 위험물 기준 위험 반경 계산 → 체류 시간 판정 → 경보)

[4] 문제점 및 검토 필요 사항
- adult(성인) 클래스 데이터 0장. 4클래스로 정의했으나 촬영 담당이 지정되지 않아
  해당 클래스는 학습·평가가 불가능함. 촬영 여부 또는 3클래스 축소 결정 필요
- 검증 데이터가 학습 데이터와 동일 일자·동일 장소·동일 물체로 구성되어 있어,
  mAP50 0.980이 실사용 성능보다 높게 측정된 것으로 판단됨.
  다른 날짜·다른 배치로 촬영한 별도 시험셋 확보 필요
- 아기와 위험물이 한 화면에 함께 있는 데이터가 45장뿐이어서,
  실제 경보가 발생하는 상황에 대한 검증이 부족함
- 팀원별로 LabelImg가 classes.txt를 자동으로 덮어써 클래스 번호가 어긋날 위험을 확인.
  클래스 목록 4줄을 팀 전체에 배포하고, 라벨 검사 스크립트를 작성해 공유함
- 구글 드라이브 업로드 시 일부 파일만 전송되는 현상 발생(사진 152장 중 77장만 업로드).
  재업로드 후 개수 확인으로 해결
