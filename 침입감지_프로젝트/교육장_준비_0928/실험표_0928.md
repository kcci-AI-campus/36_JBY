# 9/28 교육장 실험 — 이것만 하면 된다

한 줄 요약: 보드 터미널에서 **`bash 실험.sh 번호`** 만 치면 실험이 돌고, 결과 숫자는 **자동으로** `결과_0928.txt` 에 한 줄씩 쌓인다. 손으로 적는 건 딱 2가지(경보→휴대폰 지연, 휴대폰 캡처)다.

용어 3개
- **두 모드** = 팀원A님 원본 방식 (대기 ↔ 고성능)
- **4상태** = 주말에 만든 방식 (대기 / 감시 / 경계 / 경보)
- **전부** = 4상태 + 최신 INT8 모델 + CPU 클럭 1500 MHz + 경보 30 FPS 상한

## 2. 실험 (약 45분)

### 왜 이 조합인가 — 모든 경우를 다 재지 않고 최적을 찾는 법
전부 조합하면 구조 3 × 정밀도 2 × 클럭 3 × 경보 상한 3 × 입력 2 = 108가지, 장면 3개면 4시간이 넘는다. 대신 **분해 측정 + 조합 검증**으로 한다.
- 전력 = 유휴 + **초당 추론 횟수** × **추론 1회 에너지**
- 구조(두 모드 / 3상태 / 4상태)는 초당 추론 횟수를 정한다 → 장면마다 재는 **-1 ~ -3**
- 정밀도·클럭은 추론 1회 에너지를 정한다 → 4상태 위에서 하나씩 더하는 **-4 ~ -6**
- 두 효과가 따로 논다면, 장면이 달라도 "-3 대비 -4·-5·-6 의 비율"이 같게 나온다. 같으면 나머지 조합은 계산으로 채울 수 있고, 그 계산이 "108가지 중 이게 최적" 의 근거가 된다.
- 측정 없이 빼는 것: 640 FP32 + 클럭 1500 은 5.8 FPS 로 경보 최소 6 FPS 미달(9/28 새벽 실측) → 탈락.

### 방식 6가지 (장면마다 같은 순서)
| 끝번호 | 방식 | 무엇을 보려고 |
|---|---|---|
| -1 | 두 모드 (팀원A 원본) | 출발점 |
| -2 | 3상태 (두 모드 + 감시) | 감시 상태 추가 효과, 팀원A님 7번 슬라이드 값 |
| -3 | 4상태 (FP32, 클럭 2400) | 감시를 감시/경계로 나눈 효과 |
| -4 | 4상태 + 상태별 클럭 (평소 1500, 경계·경보 2400) | 클럭만의 효과 |
| -5 | 4상태 + INT8 + 상태별 클럭 | INT8 만의 효과 (-4 대비) |
| -6 | 4상태 + INT8 + 클럭 1500 고정 (전부) | 경보에서도 1500 이면 얼마나 더 주나 (-5 대비) |

4상태 방식(-3 ~ -6)은 모두 경보 30 FPS 상한. 두 모드·3상태는 원래 코드대로 상한 없음.

### 치는 것 — 장면마다 한 줄
| 순서 | 치는 것 | 장면을 이렇게 만든다 | 걸림 |
|---|---|---|---|
| 1 | `bash 실험.sh B전체` | 인형만 두고 가만히. 칼·콘센트는 화면 밖. 사람도 화면 밖 | 약 7분 |
| 2 | `bash 실험.sh C전체` | 인형을 천천히 계속 움직인다. **막대나 끈으로 움직이고 몸은 화면 밖** (사람이 찍히면 어른으로 잡힘). 칼 없음 | 약 7분 |
| 3 | `bash 실험.sh D전체` | 인형을 칼 옆에 붙여 둔다 (경보가 계속 남) | 약 7분 |
| 4 | `bash 실험.sh 지연` | 인형을 칼 쪽으로 밀어 넣기 3회, **LED 빨강 → 휴대폰 울림 스톱워치**. 첫 알림에서 휴대폰 캡처 2장. 끝나면 Ctrl+C | 5분 |
| 5 | `bash 실험.sh 4-1` → `4-2` | 빈 방 5분 / 인형만 5분 (헛알림 횟수) | 10분 |
| 6 | `bash 실험.sh 5-1` → `5-2` → `5-3` | 인형+칼 놓고 불 켬 / 불 끔 / 휴대폰 손전등만 | 각 15초 |
| 7 | `bash 실험.sh 6-1` ~ `6-4` | 6-1·6-2 는 D 장면, 6-3 칼 1.5 m, 6-4 칼 2 m (인형도 같이) | 약 5분 |

- `B전체` 는 첫 카운트다운 10초 동안만 장면을 만들면 되고, 6가지가 끝날 때까지 장면을 그대로 둔다. 사이사이 CPU 가 50 ℃ 아래로 식을 때까지 자동으로 기다린다(최대 90초).
- 하나만 다시 재려면 `bash 실험.sh C-4` 처럼 번호로.
- 결과는 전부 `결과_0928.txt` 에 자동 기록. 중간에 보려면 `bash 실험.sh 결과`.
- 1~4 가 가장 중요하다. 시간이 부족하면 거기까지만.

## 3. 손으로 적는 것 (2가지)

지연 3회 잰 값은 이렇게 적는다 (터미널에서):
```
bash 실험.sh 메모 "2번 지연 3.1 2.8 3.4초"
```
경계 완충(선택): 지연 실험 중 터미널에 `[모드] 감시 -> 경계 (비율 x.xx) 경과 t1초` 와 `-> 경보 경과 t2초` 가 찍힌다. 두 시각 차이를 메모.
```
bash 실험.sh 메모 "경계→경보 0.4초, 0.6초, 0.3초 (인형 밀 때 거리 약 20 cm)"
```
휴대폰 캡처 2장은 카톡이나 메일로 노트북에 보내 `발표슬라이드_정보윤\` 에 넣는다.

2. 클로드코드에 "결과_0928 반영해서 슬라이드 갱신해 줘" 라고 하면 3번·4-1 슬라이드 표와 대본을 바꾼다.

## 5. 문제가 생기면

| 증상 | 조치 |
|---|---|
| `bash 실험.sh 목록` 맨 아래에 "sudo 가 안 돼 클럭 전환은 빠짐" | 전부 설정이 INT8 + 30 FPS 만으로 돈다. 그대로 진행하고 비고에 적기 |
| 인형을 baby 로 못 잡음 (`[모드] 대기 -> 감시` 가 안 뜸) | 인형을 카메라에 더 가깝게, 정면으로. 그래도 안 되면 `bash 실험.sh 1-2 0` 대신 직접 `python3 detect_baby_4state.py --guard-gate --conf 0.30` 으로 확인 |
| 카메라를 열 수 없다 | 다른 프로그램이 카메라를 잡고 있음. `pkill -f detect_baby` 후 다시 |
| 결과 줄에 `?` 가 있음 | 그 실험의 `<이름>_출력.txt` 를 열어 보면 원문이 있다 |
