## 보드/ — 라즈베리파이 5에서 실행

| 파일 | 하는 일 |
|---|---|
| **`RPS_Game.py`** | **제출 과제 본체.** 2인용 가위바위보 게임. 교수님 제시 5단계(좌/우 구분 · 승패 판정 · 예외 처리 · 카운트다운과 Freeze · 스코어보드/효과음/재시작)를 모두 구현했다. INT8 tflite + MJPG + 4스레드로 68.1 FPS. |
| `RPS_Game_traced.py` | 위 게임의 **사본**에 단계별 시간 측정을 붙인 것. 원본은 수정하지 않았다. 끝낼 때 camera / preproc / inference / postproc / draw / imshow / waitKey 각각 몇 ms인지 표로 출력하고, Perfetto(ui.perfetto.dev)에서 볼 수 있는 `trace_rps.json` 을 남긴다. |
| `RPS_Game_traced_before.py` | 위 사본의 **최적화 전** 판. 교수님 원본 EX_03 설정(num_threads 없음 · MJPG 없음 · waitKey(10) · 카메라 스레드 없음)으로 되돌렸다. 게임 로직과 검출 코드는 동일하므로, 둘을 각각 30초 돌리면 파이프라인 최적화의 Before/After 가 같은 조건에서 나온다. 실측 결과 한 프레임 53.61 → 14.46 ms (3.7배). |
| `trace_util.py` | 위 측정에 쓰는 도구. Chrome Trace Format(공개 형식)으로 기록한다. NPU SDK가 제공하던 타임라인을 직접 만들어 본 것. |
| `EX_01_Auto_Capture.py` | **학습 사진 자동 촬영기.** 교수님 예제는 키를 누를 때마다 한 장씩 찍고 항상 `img_0001`부터 저장해 기존 사진을 덮어쓴다. 이 도구는 1초마다 자동 촬영하고, 숫자 키로 클래스 꼬리표를 파일명에 남기며, 기존 번호 뒤에서 이어 붙인다. 화면만 좌우 반전하고 저장본은 원본 그대로다. |
| `bg_check.py` | 카메라에 보이는 **배경의 밝기(V)와 색(R−B)** 을 1초마다 출력해 학습 데이터 범위(V 131~176, 무채색)와 비교한다. "밤색 티 앞에서 인식이 안 된다"를 수치로 확인하려고 만들었다. 창을 띄우지 않아 SSH만으로 동작한다. |
| `make_sounds.py` | 승/패/무 효과음 wav 를 사인파로 생성한다(외부 음원 없이 5단계 요구를 만족시키기 위해). |

## 데이터셋도구/ — PC에서 실행

| 파일 | 하는 일 |
|---|---|
| **`make_dataset.py`** | **학습 데이터셋 생성기.** LabelImg 가 뱉는 PascalVOC(xml)을 YOLO(txt)로 변환하고, 여러 출처를 병합하고, 내용 해시로 중복 사진을 걸러 내고, `data.yaml` 을 쓰고, 검사 후 zip 으로 묶는다. 변환 공식은 교수님 데이터 박스 132개와 1:1 대조해 검증했다(좌표 최대 차이 0.00064 픽셀). |
| `check_labels.py` | 라벨 **전수 검사기.** 폴더 이름과 라벨 클래스가 맞는지, 좌표가 0~1 안에 있는지, 짝 없는 라벨이 있는지, `classes.txt` 순서가 바뀌지 않았는지 확인한다. 이런 오류는 학습이 **경고 없이** 진행되므로 사람이 눈으로 찾을 수 없다. |
| `mark_background.py` | 손이 없는 사진에 **빈 txt** 를 만들어 "확인했고 손이 없다"를 표시한다. 빈 txt 와 txt 없음을 구별하기 위한 것이다(전자는 배경 학습용, 후자는 아직 라벨링 안 한 것). |
| `fix_label_place.py` | LabelImg 에서 `Change Save Dir` 을 깜빡해 다른 폴더에 쌓인 라벨을, 같은 이름의 사진이 있는 폴더로 되돌린다. |
| **`make_testset_today.py`** | **고정 시험지 생성기.** 2026-09-18 에 직접 촬영·라벨링한 233장(박스 328개, 배경 25장 포함)을 채점용으로 묶는다. 어느 학습에도 쓰지 않아 여러 모델을 같은 잣대로 비교할 수 있다. |
| `make_holdout.py` | 촬영한 사진 중 일부를 규칙적으로(난수 아님) 떼어 내 **학습에 절대 넣지 않는 시험지**로 만든다. |
| `make_testset.py` | 위 도구의 초기 버전(135장). 기록용으로 남긴다. |
| **`make_ab.py`** | **A/B 실험용 데이터셋 생성기.** 사진은 완전히 동일하고 팀원 촬영분 88장의 라벨만 A(팀원)/B(다시 라벨링)로 바꾼 두 벌을 만든다. "라벨 품질이 성능에 영향을 주는가"를 라벨 외 조건을 모두 고정한 채 재기 위한 것이다. |

## Colab학습/ — 구글 Colab 에서 실행

`EX_02_RPS_Pretrained_YOLO_Finetuning.ipynb` — 교수님이 주신 학습 노트북에 **이번 프로젝트에서 직접
추가한 셀들이 함께 들어 있다.** 보고서에 실린 수치가 어디서 나왔는지가 이 노트북에 그대로 남아 있다.

| 추가한 셀 | 보고서 어디에 쓰였나 |
|---|---|
| 고정 시험지(233장)로 v1/v3/v9 채점 | 4-1 두 시험지 비교표 |
| A/B 데이터셋 학습 + hold40 채점 | 4-5 라벨 품질 가설 기각 |
| 같은 데이터·시드만 바꿔 3회 학습 | 4-1 실행 간 변동폭 0.142 |
| 신뢰도 문턱값 훑기 | 4-6 판정률 3.1배 |
| `args.yaml` 의 `data:` 로 학습 폴더 식별 | 4-2 2 epoch 중단 사고 발견 |
| BEST 선택 시 epoch < 80 이면 RuntimeError | 같은 사고의 재발 방지 |

실패한 셀(GPU 사용량 한도로 멈춘 것)도 지우지 않고 남겼다. 과정을 그대로 보이는 편이 낫다고 판단했다.

## 실행 순서 (재현하려면)

```
1. 보드에서 촬영        python3 EX_01_Auto_Capture.py
2. PC에서 라벨링        LabelImg (YOLO 형식)
3. 라벨 검사            python check_labels.py <폴더들>
4. 배경 사진 표시       python mark_background.py <배경 사진들>
5. 학습 데이터셋 생성   python make_dataset.py        -> RPS_Dataset_YOLO_vN.zip
6. 시험지 생성          python make_testset_today.py  -> RPS_TestSet_today.zip
7. Colab 에서 학습      EX_02 노트북 (교수님 제공)
8. 보드에서 게임        python3 RPS_Game.py my_best_int8_v3.tflite
```
